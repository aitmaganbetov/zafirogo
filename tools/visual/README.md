# tools/visual — визуальное сравнение старых и новых страниц

Инструмент Этапа 3 (`docs/stage-3-plan.md`, блок F2): одна команда поднимает старый Laravel и новый сервер на одних
и тех же демо-данных с одним и тем же «сейчас», входит в оба одинаковым пользователем, снимает одни и те же страницы
в одинаковом окне и теме и сравнивает снимки попиксельно (pixelmatch). Результат — HTML-отчёт «старое | новое | разница».

```sh
task visual                               # все страницы tools/visual/pages.json
task visual -- --page dashboard           # одна страница (несколько — через запятую)
task visual -- --page dashboard --keep    # оставить серверы запущенными…
task visual -- --page dashboard --reuse   # …и снимать повторно без перезапуска (секунды)
task visual -- --no-build                 # не пересобирать фронт и бинарник нового сервера
task visual:stop                          # остановить серверы после --keep
```

Отчёт: `tools/visual/report/index.html` (открыть в браузере), итог для машин — `tools/visual/report/summary.json`.
Код выхода `1` — ошибка снимка или перенесённая страница (`status: ported`) сверх порога.

Нужны: Docker, Go (версия из `server/go.mod`), Node 22, `goose` (`task tools`), Chromium Playwright (`web/`), старый
проект в `../Zafiro` (или `ZAFIRO_SRC`), `composer` при первом запуске (скачать `vendor/`; дальше — кэш).
Первый прогон — несколько минут (`composer install`, если нет кэша `tools/php-oracle`; копия старого проекта;
`npm run build` старого фронта; сборка нового), следующие — ~25–30 с (замер: 2 страницы + каркас, 10 снимков пар — 22–29 с).

## Как это устроено

| Шаг | Файл | Что делает |
|---|---|---|

### Одинаковые данные

- **Одни id** в обеих базах (явные id в загрузчиках): URL вида `/club-computers/5` совпадают.
- **Суммы** в `demo.json` — строки тенге (`"1500.00"`); старый пишет их в `decimal`, новый — в тиыны без float.
- **Балансы** в новом — `billing.SetInitialBalance` (ledger, операция `initial_balance`): прямой UPDATE баланса запрещён
  триггером. В старом — `member_balances` напрямую (как `UserController::store()`).
- **Кассовые операции** (`operations`: смены, продажи, пополнения, расходы, закрытия) выполняет **сервис кассы каждого
  приложения** с «сейчас» = `at`: старый `CashRegisterService` под `Carbon::setTestNow`, новый `cash/service` с часами
  `Now`. Чеки, остатки товаров, бонусы, тексты операций и журнал получаются логикой самого приложения — расхождение
  в них видно на снимке (и это не ошибка загрузчика).
- **Пароль** всех пользователей — `login.password` (`zafiro-demo-2026`); в базах — один и тот же bcrypt-хэш
  `login.password_bcrypt`. Новый сервер принимает старый bcrypt и перехеширует его при первом входе.
- **Роли** для входа — `login.roles` (`superadmin`, `owner`, `admin`, `cashier`, `operator` → id пользователя).

### Одинаковое время

- Старый: `Carbon::setTestNow()` на каждый запрос (вставка в `public/index.php` **копии**, время — из
  `storage/framework/visual-now`). Cookie сессии — до закрытия браузера (`SESSION_EXPIRE_ON_CLOSE`), иначе срок,
  посчитанный от замороженного «сейчас», браузер считает истёкшим.
- Новый: `ZAFIRO_DEV_FIXED_NOW` (ключ конфигурации `dev.fixed_now`, только `dev`/`test`, в `prod` — ошибка валидации):
  часы денег (billing), кассы и обработчиков админки (`httpserver.Options.Now`). **Не** действует на `now()` в SQL,
  сроки токенов и сессий, время проводок ledger и audit_log.
- Браузер: `page.clock.install()` с тем же «сейчас»; таймеры и `requestAnimationFrame` идут только вперёд на
  `VISUAL_SETTLE_MS` (3 с) после загрузки — анимации (Chart.js и т. п.) успевают закончиться; часы в шапке уходят
  на те же несколько секунд вперёд в обоих (и закрыты маской `@clock`).

### Стабилизация снимка

`locale: ru-RU`, `timezoneId: Asia/Almaty`, `deviceScaleFactor: 1`, `reducedMotion: reduce`, service worker выключен,
`localStorage`: `zafiro.theme` = тема, баннер установки PWA отклонён, сайдбар развёрнут. После загрузки: ожидание сети
(не дольше 5 с — опросы старого JS), `document.fonts.ready`, картинки, CSS без анимаций и курсора, `animations: disabled`.
Раскладки на `100vh` с прокруткой внутри блока (`admin-app`): окно растягивается на непрокрученный остаток
(`growViewportToContent`), CSS страниц не меняется. Полностраничный снимок — не выше 12 000 px (выше Chromium не
снимает и падает): у длинных страниц (wiki) снимается верх, в отчёте — «Обрезано».

Устойчивость: упавший браузер воркера заменяется новым, снимок после падения вкладки или браузера повторяется один раз
(в отчёте — «Повтор»); Chromium держит общую память в `/dev/shm`, а не во временных файлах на диске. Страницы
суперадмина (`role: superadmin`) снимаются по порядку в одном воркере: каждый вход суперадмина пишется в журнал
платформы, и параллельный вход между снимками старого и нового менял бы число строк в паре.

Внешние ресурсы старых страниц не берутся из сети: Font Awesome 6.4.0 (cdnjs) и Chart.js 4.5.1 (jsdelivr) — те же
файлы из npm-пакетов `tools/visual/node_modules`; Google Fonts (Inter) — один раз через `curl` в
`~/.cache/zafirogo-visual/external`; остальное внешнее блокируется (список — в отчёте у каждого снимка).

## Как агенту экранов добавить страницу

1. Добавьте запись в `pages.json` → `pages`:

   ```json
   {
     "id": "cash-register",
     "old": "/cash-register",
     "new": "/cash-register",
     "role": "cashier",
     "waitFor": "[data-cart]",
     "mask": ["@clock", "@relativeTime"],
     "status": "ported",
     "note": "Касса (cash-register/index.blade.php)"
   }
   ```

   - `role` — кто входит (`login.roles`); `null` — без входа (публичные страницы, вход, регистрация).
   - `viewports` (`desktop` 1440×900, `mobile` 390×844) и `themes` (`light`, `dark`) — по умолчанию все.
   - `mask` — селекторы **живых** элементов (закрашиваются пурпурным в обоих снимках). Наборы: `@clock` (часы шапки),
     `@relativeTime` (`[data-relative-time]`: «5 мин назад»), `@badges` (счётчики сайдбара и колокольчика). Разные
     селекторы для старого и нового — `{"old": [...], "new": [...]}`. По умолчанию — `["@clock"]`.
   - `hide` — блоки, которые убираются из раскладки в обоих снимках (`display: none`), когда от окружения стенда
     зависит не только их содержимое, но и высота (СУБД, журнал ошибок машины, живые показатели с переносом строк):
     маска закрашивает, но не выравнивает остаток страницы. Формат — как у `mask`; причина — в `note`.
   - `fullPage: false` — только окно (например, каркас без контента).
   - `media: "print"` — печатная версия (`@media print`: чек, X/Z-отчёт).
   - `maxDiffPercent` (по умолчанию 0.5) и `pixelThreshold` (0.1) — пороги; поднимать только с причиной в `note`.
   - `host` — хост вместо `localhost` в адресах обоих приложений: страницы кабинета суперадмина — `admin.localhost`
     (оба сервера запускаются с доменом кабинета `VISUAL_SUPERADMIN_HOST`, по умолчанию `admin.localhost`, Q-069).
   - `status`: `pending` — экран ещё не перенесён (расхождение только в отчёте), `ported` — перенесён
     (расхождение сверх порога — красный `task visual`).
2. Если странице нужны данные, которых нет, — дополните `fixtures/demo.json` **и оба загрузчика**
   (`old/seed.php`, `server/cmd/visual-seed`). Деньги — только строками тенге; движения денег в новом — через
   сервисы/ledger, как в существующих операциях. `go test ./cmd/visual-seed` проверяет, что фикстура читается.
3. `task visual -- --page <id> --keep`, правка, `task visual -- --page <id> --reuse` — пока не станет зелёным.
4. В отчёт агента — процент расхождения по каждому варианту и объяснение остатка.

Новый сервер показывает «сейчас» из `dev.fixed_now` только там, где время берётся из часов приложения: в обработчиках
используйте `opts.Now` (или передавайте время параметром в SQL), а не `now()` в запросе — иначе «сегодня» на снимке
будет реальным днём, а не днём демо-данных.

## Как читать отчёт

Карточка = страница × окно × тема: снимок старого, нового, карта разницы и процент отличающихся пикселей от площади
большего снимка. На карте разницы: красный — другое/светлее в новом, голубой — темнее в новом, жёлтый — сглаживание (не считается);
полоса, которой нет в меньшем снимке (разная высота страницы), целиком считается расхождением. Под снимками — URL после
переходов, способ входа (`form` — форма `/login`, `api` — `POST /api/auth/login`, пока форма не перенесена), маски,
ошибки консоли и заблокированные внешние запросы. Фильтры сверху: расходится / не перенесено / ошибки / совпадает.

## Какие расхождения допустимы

- **Рендеринг шрифтов и сглаживание** — покрываются порогами: `pixelThreshold` 0.1 (цвет) и `maxDiffPercent` 0.5 %;
  сглаживание pixelmatch не считает. Повторный прогон одних и тех же страниц даёт 0–17 отличающихся пикселей.
- **Данные «сейчас»** (часы, «N мин назад», живые счётчики) — маски, а не порог.
- **Осознанные отличия переноса** (новый шрифт из npm вместо Google Fonts, исправления из `DECISIONS.md`) — маска или
  порог с объяснением в `note` и вопросом в `docs/open-questions/`.

Недопустимо: другой текст, суммы, порядок строк, отступы, цвета, иконки — это и есть то, что ловит инструмент.

## Ограничения

- Статус ПК «в сети» в новом сервере живёт в Valkey (поток агента); демо-данные пишут только `club_computers.status`
  и `last_seen_at` (как старый `ClubComputerSessions`), сверка присутствия на визуальном сервере — раз в сутки.
  Если экран берёт «в сети» из Valkey — дополните `visual-seed` записью присутствия (`docs/open-questions/stage3-visual.md` V-2).
- Время проводок ledger и audit_log — время загрузки (таблицы только добавляются); журнал действий выровнен по `at`.
- Задачи мониторинга нового (`monitoring-collect`, `monitoring-flush`, `monitoring-clubs`) в стенде выключены
  (`ZAFIRO_DEV_DISABLE_WORKERS`, только dev/test), как планировщик старого: экраны «Сервер» и карточки клуба не
  показывают трафик самого прогона (`docs/open-questions/stage3-visual.md` V-11).
- Заказы с ПК в демо-данных — готовые записи без списания денег (балансы клиентов от них не меняются ни в старом, ни в новом).
- Пока экран входа не перенесён, новый входит через API: SPA должна восстановить сессию по refresh-cookie.
- Мобильный вид — окно 390×844 с `isMobile`/`hasTouch` в Chromium, не реальный телефон.

# zafirogo — правила разработки

Перенос биллинга компьютерных клубов Zafiro с Laravel на Go + React.
Облачный SaaS: каждый клуб — тенант (`club_id`).
Старый проект (источник правды, только чтение): https://github.com/aitmaganbetov/Zafiro (локально `../Zafiro`).

## Принятые решения (не пересматривать без вопроса владельцу)

1. Полный перенос на Go + React. Клубы работают на старом Laravel, пока новый проект не готов.
   Переход поклубно (по тенантам), с переносом данных MySQL → Postgres (`tools/migrate-from-mysql`).
2. **Дизайн и бизнес-логика сохраняются.** Это перенос, а не редизайн: те же экраны и Tailwind-классы,
   те же суммы до тиына.
3. API агента и гостя спроектированы заново (`proto/agent/v1`), совместимость со старым не нужна.
   Мобильные приложения (Flutter) отложены.
4. Приоритеты — скорость и безопасность. Масштаб: 5 000 ПК сейчас, до 50 000 ПК.
5. Агент остаётся на C#; меняется слой связи. Минимальная нагрузка на CPU/RAM: служба отдельно от UI,
   WebView2 только когда показан экран блокировки или лаунчер, Native AOT, где возможно.

## Стек

- Go (версия в `server/go.mod`): chi, slog, koanf; REST по OpenAPI (`api/openapi.yaml`, oapi-codegen strict server);
  WebSocket для real-time в браузер; gRPC (bidirectional stream + mTLS) для агента, контракт в `proto/`.
- PostgreSQL + pgx + sqlc (никаких ORM), миграции goose (`db/migrations`), запросы `db/queries`.
- Valkey (кэш, сессии, rate limit), NATS JetStream (события между инстансами, фоновые задачи).
- Фоновые задачи — воркеры в Go (`internal/worker`), не cron. Не запускать дважды на нескольких инстансах
  (лидер или JetStream-консьюмер).
- Один бинарник: фронт вшит через `embed.FS` (`server/internal/webui`).
- Фронт `web/`: React 19 + TypeScript + Vite, TanStack Router/Query/Table/Virtual, Tailwind 4
  (shadcn/ui только там, где не ломает текущий дизайн), react-hook-form + zod, i18next (ru/kk/en),
  типы API из OpenAPI (openapi-typescript).
- Тесты: Go `testing` + testcontainers (реальный Postgres), Vitest, Playwright (включая визуальное
  сравнение скриншотов старых и новых страниц).
- Версии закреплены точно (без `^`/`~`, без `@latest` в CI). Обновления приходят через Dependabot.

## Команды (Taskfile)

- `task tools` — установить закреплённые версии генераторов и линтеров.
- `task dev` — docker-compose (Postgres, Valkey, NATS) + сервер + Vite.
- `task gen` — sqlc, oapi-codegen, buf (Go), openapi-typescript. Сгенерированный код коммитится.
- `task test` — `go test ./...` + Vitest. Интеграционные: `go test -tags=integration ./...` (нужен Docker).
- `task lint` — go vet, golangci-lint, govulncheck, gosec, eslint, tsc.
- `task build` — один бинарник `bin/zafiro` со вшитым фронтом.
- `task db:migrate` — goose up.

## Деньги

- Суммы — `int64` в тиынах. Никогда float (ни в Go, ни в TS, ни в JSON: в API — целые тиыны).
- Формулы и округления переносить **буквально** из старого кода (`intdiv`, «+5000 / 10000» и т.п.),
  с комментарием-ссылкой на файл и метод Laravel, откуда взято:
  `// Laravel: app/Services/TopUpBonus.php TopUpBonus::forAmount()`.
- PHP 8.3 `round()` сначала округляет десятичную запись (`round(100.005*100) = 10001`),
  а наивный Go `math.Round(x*100)` даёт 10000. Там, где старый код округлял float, использовать
  общий пакет с эквивалентом PHP-округления и тестами на граничных значениях (`docs/business-rules.md` §2).
- Все движения денег — через журнал операций (ledger) с ключом идемпотентности.
  Баланс не меняется «просто обновлением поля».
- Любое изменение логики расчётов — сначала тест со сценарием из старой реализации
  (`docs/golden-scenarios.md`, `docs/business-rules.md`).

## Тенантность

- Каждая тенантная таблица имеет `club_id`. Каждый sqlc-запрос к тенантной таблице фильтрует по `club_id`.
- Второй рубеж — Row-Level Security в Postgres (`app.club_id` ставится в транзакции).
- Клуб берётся из аутентификации (сессия сотрудника, сертификат ПК, API-ключ), никогда из параметров запроса.

## Безопасность

- Пароли — Argon2id. Короткие access-токены + ротация refresh-токенов.
- Роли и права — как в старом (`app/Support/ClubPermissions.php`, `ClubRoles.php`, `StaffPermissions.php`).
- Rate limiting на тех же маршрутах, где он был в Laravel (`throttle:` — список в `docs/MIGRATION.md`).
- Аудит-журнал всех действий с деньгами, тарифами и правами — только добавление.
- Секреты не в репозитории, не в логах, не в журнале действий, не в кэше.
- Агент: mTLS, регистрация ПК по одноразовому коду, отзыв сертификата, обновления подписаны Ed25519.
- CI: `go vet`, golangci-lint, `govulncheck`, `gosec`, Dependabot.

## Производительность

- Heartbeat/статус ПК не писать в Postgres на каждый пинг — держать в памяти/Valkey,
  в базу только изменения состояния.
- Опросы (polling) заменять на push: WebSocket для админки, стрим для агента.
- Агрегаты (суммы, счётчики, графики) — в SQL, не в Go после выборки всего.
- Списки, которые растут с данными, — с пагинацией (лучше keyset) или поиском.
- Фильтры по времени — диапазоном (`>= start AND < end`), не функциями над индексируемыми колонками.
- Составные индексы с `club_id` для тенантных выборок по периоду и с сортировкой.
- Таблицы журналов и истории — партиционирование по месяцам.

## Локализация

- Тексты интерфейса — ru / kk / en. Ключ — русский текст, как в старом проекте (`t('Русский текст')`).
- Подстановки — плейсхолдерами, не склейкой строк. Множественное число: ru — 3 формы, kk — 1, en — 2.
- Переводы общие для всех клубов и редактируются в суперадминке — не вставлять их как HTML.
- Данные из БД и маркеры для сравнений через `t()` не пропускать.

## Фронтенд

- Разметку и классы Tailwind переносить из Blade без изменений; расхождения — только осознанно,
  с вопросом в `docs/OPEN_QUESTIONS.md`.
- Внешние скрипты/стили — только с закреплённой версией и только на страницах, которые их используют.
- Не добавлять CSS-классы «на будущее»; удалять стили вместе с разметкой.

## Тесты

- Не хардкодить окружение (URL, порты) в ожиданиях.
- Денежные сценарии — табличные Go-тесты по `docs/golden-scenarios.md` (ID сценария в имени подтеста).

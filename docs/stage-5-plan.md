# Этап 5 — переход клубов: перенос данных и новый агент

Цель: перевести первый клуб со старого Laravel на новый сервер без потери данных и денег.

## Перенос данных (`server/cmd/migrate-from-mysql`, описание — `tools/migrate-from-mysql/README.md`)

| Шаг | Что делаем |
|---|---|
| M1. Ядро | Чтение одного клуба из MySQL старой схемы → запись в Postgres новой: все 42 таблицы, деньги `× 100` в тиыны, id сохраняются, последовательности сдвигаются (Q-029), партиции под старые даты, балансы — входящими остатками через ledger (Q-004), режимы `plan` (сухой прогон) и `apply`, повторный запуск безопасен. |
| M2. Производные данные и сверка | JSON → формат v2 (Q-003), `tariff_sales`, `cash_transactions.income_kind`, `session_purchases.zone_id/source` из журнала действий, токены приложений и API-ключи, секреты с расшифровкой `APP_KEY` (Q-050), файлы логотипов, картинок входа и новостей; отчёт сверки: суммы балансов, кассы, склада, число строк до и после — расхождение блокирует переход. |
| Проверка | Источник — настоящая старая схема MySQL (миграции старого проекта) с демо-данными; после переноса новый сервер проходит сквозные сценарии на перенесённых данных. |

## Новый агент (`agent/`)

| Шаг | Что делаем |
|---|---|
| A1. Связь | Библиотека связи на gRPC (`proto/agent/v1`): регистрация по коду и ключу образа, mTLS, поток с командами и повторной доставкой, токен гостя, все unary-методы; служба Windows отдельно от UI (решение 5 в CLAUDE.md); проверка на Linux против Go-сервера в Docker (.NET 10). |
| A2. Интерфейс | Перевод UI (WPF + WebView2, экраны входа, лаунчер, магазин) на новую библиотеку; WebView2 только когда показан экран. Сборка и подписанный установщик в CI. |

## Готово, когда

- Демо-клуб переносится одной командой, отчёт сверки без расхождений, новый сервер работает на перенесённых данных.
- Агент регистрируется, держит поток и выполняет все сценарии гостя против нового сервера.

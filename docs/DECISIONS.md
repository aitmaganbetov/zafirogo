# Решения по открытым вопросам

Владелец поручил принять решения самостоятельно (30.10.2026). Этот файл — решения оркестратора.
Отменить или изменить любое решение может только владелец; код, зависящий от решения, ссылается на его ID.

## Принципы

1. **Деньги — точно.** Целые тиыны везде; никаких float-сравнений; неоднозначный ввод отклоняется, а не округляется.
2. **Поведение старого кода сохраняется**, кроме явных багов, которые теряют деньги, дают доступ не туда
   или ломают поклубный переход. Такие баги исправляются, с тестом и записью здесь.
3. **Новые функции не добавляются** в рамках переноса (это не редизайн).
4. **Безопасность по умолчанию**: если старый код не защищал (лимиты, токены), новый — защищает.
5. По остальным вопросам принимается **рекомендация** из исходного файла вопросов, если ниже не сказано иное.

## Деньги и расчёты

| ID | Решение |
|---|---|
| Q-001 | Да: `bigint` тиыны под прежними именами колонок. Перенос `× 100`. |
| Q-002, CQ-3 | **Ввод сумм с > 2 знаками после точки отклоняется (422)** во всех формах и RPC — единое правило вместо «касса округляет, переводы отклоняют». Остаток кассы, «хватает ли средств» и лимиты сравниваются **точно в тиынах**, не во float. Для корректного ввода (≤ 2 знаков) суммы совпадают со старыми. |
| Q-003 | Новые записи JSON (чеки, заказы, настройки уровней) — в тиынах и базисных пунктах с полем версии `"v": 2`. Чтение поддерживает и старый формат (конвертация по правилам PHP 8.4). Перенос данных переводит всё в v2. |
| Q-004 | Ошибка знака старого кода не переносится. Новые операции не дают уйти в минус (ledger). `CHECK (balance >= 0)` — после проверки данных при переносе; отрицательные остатки переносятся входящим остатком с пометкой в отчёте переноса. |
| Q-005 | Расхождения в 1 тиын недопустимы для корректного ввода; сверка при переносе — пересчёт балансов из истории старой БД в отчёте переноса. |

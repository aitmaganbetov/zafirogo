## Проверка

- **Эталонные сценарии.** Все 36 GAP-сценариев подтверждены прогоном старого кода; в трёх исправлены побочные утверждения,
  числа совпали. Сквозные интеграционные тесты (реальный Postgres, testcontainers) покрывают P1-сценарии покупок, сессий,
  возвратов, пакетов, пересадки, истечения, гостевых сессий, кассы, X/Z, склада, пополнений и переводов.
- **Дифференциальные тесты против старого PHP** (тег `phporacle`):

  | Область | Вызовов | Расхождений |
  |---|---:|---:|
  | `round()` и денежные преобразования | 310 449 | 0 |
  | Бонус за пополнение, уровни, лояльность | 325 000 | 0 |
  | `PaymentRules`, `WeeklyPeriods`, цены, полная покупка `sell()` через БД | 27 500 | 0 |
  | `SessionSettlement::settle()` | 44 сценария | 0 |

- **Инварианты** проверяются после каждого интеграционного сценария: балансы клиентов = сумма проводок, остаток кассы
  по журналу = остаток смены. Конкурентность: параллельные списания, повторы с одним ключом, последняя единица товара.
- CI зелёный: vet, golangci-lint, govulncheck, gosec, unit- и интеграционные тесты, миграции.

## Главные находки

1. **Прод работает на PHP 8.4+** (`composer.lock` старого проекта требует ≥ 8.4.1). `round()` в 8.4 отличается от 8.3
   на 4,3 % «опасных» значений; перенос сделан под 8.4 (решение MQ-1).
2. **Ошибки знака старого кода** (`amountToCents("-0.01") = +1`, `formatCents(-50) = "0.-50"`) не переносятся:
   новый код считает в `int64`. Отрицательные балансы в проде проверит инструмент переноса (PQ-8, Q-004).
3. **Журнал действий участвовал в расчётах** (лимит продаж тарифа, зоны пересадки, вид прихода в X/Z). В новой схеме
   это отдельные данные: `tariff_sales`, `session_purchases.zone_id/source`, `cash_transactions.income_kind`.
   При переносе данных их нужно заполнить из `activity_logs`.
4. Старое поведение, перенесённое буквально, но похожее на баг: неактивный тариф продаётся по id (SV-2),
   время брони в ошибке агента в UTC (SV-9), просроченный пакет не удаляется (GAP-014), сравнение «хватает ли наличных»
   во float (CQ-3). По решениям 30.10.2026 все четыре исправлены (см. «Принятые решения»).

## Что осталось за рамками Этапа 1

- HTTP/gRPC-слой (REST админки, протокол агента) — сервисы готовы к подключению.
- Журнал действий интерфейса (`activity_logs`) и вебхуки — сервисы возвращают всё нужное (SV-8, CSQ-5).
- Партиционирование старых журналов (`activity_logs` и др.), инструмент переноса данных MySQL → Postgres.
- Остальные фоновые задачи (подписки, метрики, очистка) — по образцу воркера истечения сессий.

# Этап 3, группа 4 — тарифы, брони, новости, задачи, чат, журнал действий, уведомления: вопросы и решения

Владелец поручил решать самостоятельно по принципам `docs/DECISIONS.md`; ниже — решение и причина по каждому пункту.
Код: `api/{tariffs,reservations,news,todos,chat,activitylogs,notifications}.yaml`,
`server/internal/http/sections/<раздел>`, `server/internal/{reservations,chat,club}`, `web/src/features/<раздел>`.

- [x] **G4-1. Картинки новостей без общего диска (GG-11 для новостей).** В старом — файл на локальном диске Laravel
  (`NewsManager::storeImage()`), публичный `GET /news-images/{news}/{file}`. У нового сервера несколько инстансов без
  общего диска.
  - Решение: байты картинки — в таблице `news_images` (миграция `0018_news_images.sql`, одна картинка на новость,
    ≤ 2 МБ, PNG/JPEG, RLS как у `news`); `news.image_path` хранит путь прежнего формата (`news/<club>/<40>.png`) —
    по нему сверяется имя файла в URL и строится адрес для агента (`guestapi` уже строит его так же). Маршрут
    `GET /news-images/{news}/{file}` — в разделе `news`, через пул `zafiro_platform` (клуб из запроса неизвестен),
    заголовки как в старом (`immutable`, `nosniff`, `CSP default-src 'none'`). Перенос данных
    (`tools/migrate-from-mysql`) должен скопировать файлы `storage/app/news/**` в `news_images` — пункт для переноса.
  - Логотип клуба и картинку экрана входа (группа 5) можно хранить так же (своя таблица или общая) — решение группы 5.

- [x] **G4-2. Журнал: описание ключом и параметрами (W-3).** Новые записи моих разделов (`tariff.*`, `reservation.*`,
  `news.*`, `todo.*`) пишут `description` — русский текст (как `__()` старого кода: его читают поиск, отчёты и старые
  строки) и `details._t = {key, params}` (`activity.Entry.Translated`). Экран журнала и колокольчик переводят такие
  описания на язык клуба при показе (`httpx.Deps.T`); `_t` в списке подробностей не показывается. Старые и
  перенесённые строки — текст как есть. Другим разделам достаточно заменить `Description: …` на
  `.Translated(ключ, параметры)`.

- [x] **G4-3. Ярлыки новых событий журнала.** `time.package_expired` (Q-011) и `computer.session_expired` (Q-010) пишет
  только новый код. Решение: ярлыки «Сгорание абонемента» и «Окончание сессии ПК» в конце списка `EVENT_LABELS`
  (`server/internal/activity/labels.go`); фильтр «Тип события» принимает их. Переводов kk/en у этих ключей в
  `database/translations` нет — добавить в суперадминке (до этого показывается русский текст). События, которые
  писал и старый код, но которых не было в `EVENT_LABELS` (`time.package_started`, `time.package_kept`,
  `time.refunded`), как и раньше, без ярлыка (показывается код события) и не фильтруются — как в старом.

- [x] **G4-4. Пагинация журнала — keyset.** Старый: `paginate(50)` с номерами страниц и `total`. `activity_logs`
  партиционирована по месяцам, `OFFSET` на больших журналах дорог. Решение: keyset по `(created_at, id)` (курсор) и
  вид пагинации `simple-tailwind` Laravel («Назад»/«Вперёд», стек курсоров в адресе); «Записей: N» остаётся (COUNT с
  теми же фильтрами по диапазону дат). Визуально отличается только блок пагинации, когда записей больше 50.
  Брони (день клуба) и новости (20 на страницу клуба) — номерами страниц, как в старом: списки ограничены днём/клубом.

- [x] **G4-5. Бронирование из карты клуба (`POST /reservations/many`) и поиск клиента.** Сервис броней
  (`internal/reservations`: `ComputerReservations::create/cancel/arrive`) общий; операции `createReservationsMany`
  (`POST /api/reservations/many`) и `searchReservationCustomers` (`GET /api/reservations/customers`, лимит 60/мин)
  реализованы в разделе `reservations` — экран карты клуба (группа 1) вызывает их, своих путей с броней не заводит.

- [x] **G4-6. События броней.** Старый код событий не писал. Решение: `computer.reservation_changed` (вебхук
  интеграций, каталог `docs/realtime.md`) и `reservation.changed {reservation_id, computer_id, action, date}` для экрана
  «Брони» (право `reservations.view`) — список перечитывается по событию.

- [x] **G4-7. Чат: доставка ответа на ПК и бейдж.** Ответ сотрудника уходит гостю командой `ChatMessageReceived` на
  каждый ПК клуба, где гость вошёл (по присутствию, как `BalanceChanged`), после коммита (`httpx.Deps.ChatToGuest`,
  `server/internal/app/chat_guest.go`). Сообщение гостя (`guestapi.SendChatMessage`) и отметка прочитанным
  (открытие диалога отвечающим) пишут `chat.unread {unread}` (живой бейдж «Чат», Q-063) и `notifications.changed`.
  Экран чата перечитывает страницу по `chat.message` (в событии только id — текст по REST). Открытие диалога
  суперадмином в режиме просмотра не помечает сообщения прочитанными (режим «только чтение»).

- [x] **G4-8. Колокольчик: обновление по WebSocket.** `notifications.changed` пишется в той же транзакции для событий
  журнала из списка колокольчика (`activity.BellEvents` — общий хук `activity.Record`), чата; клиент перечитывает
  `GET /api/notifications` также по `chat.unread`, `shop_order.*`, `stock.*` (заказы и остатки — источники колокольчика).
  «ПК не на связи»: в старом — `last_seen_at` старше 90 с при `status <> offline`; в новом `last_seen_at` не пишется
  на каждый пинг, поэтому ПК, чей агент сейчас в сети по присутствию (Valkey), не считается.

- [x] **G4-9. «Новая версия агента» в колокольчике.** `AgentUpdate::status()` — релиз из `platform_settings`
  `agent_release` (`AgentReleaseSetting`, группа 1) и версии агентов клуба; сравнение версий — `clubmap.IsOutdated`
  (общий пакет группы 1). `released_at` — как `Carbon::parse()` (пусто — сейчас, нечитаемо — начало дня).

- [x] **G4-10. Форма тарифа: тексты правил.** Правила `StoreTariffRequest` перенесены по порядку (все ошибки сразу,
  `httpx.FormErrors`), цена — тиыны 0…999 999 999 999 (PQ-4, тексты `min:0`/`max:9999999999.99`). Отличия текстов:
  `required_if` (лимиты использования/количества) — текст правила `required` («The usage limit value field is
  required.» вместо «…when usage limit enabled is 1.»), `date_format` периодов — «The … field is invalid.» (шаблонов
  этих правил нет в `httpx.RuleMessage`); форма показывает первую ошибку над формой, как `$errors->first()`.
  `user_roles` в форму не добавлен (PD-11). Аудит `audit_log` (категория `tariff`): `tariff.created|updated|deleted`
  с `before/after` (цена, длительность, активность, зоны).

- [x] **G4-11. «Продано N из M» у тарифа с лимитом количества.** Старый считал `COUNT(activity_logs tariff.purchased)`;
  новый — счётчик `tariff_sales.sold` (тот же, что проверяет агент при покупке, Q-007). Перенос данных заполняет его
  числом записей журнала (бэклог Q-007).

- [x] **G4-12. Время «сейчас» экранов.** «Сегодня» задач и броней, «сейчас не продаётся» тарифов, «N минут назад»
  колокольчика берут время из часов приложения (`Deps.NowFunc`, `dev.fixed_now`), а не `now()` SQL (V-1).

- [x] **G4-13. Новости платформы.** Шаблон `news/index.blade.php` общий; перенесена клубная часть (`/news`). Режим
  платформы (`/platform-news`, суперадминка) — группа 6: та же разметка (`web/src/features/news/NewsPage.tsx`) с другим
  API; таблица `news_images` уже принимает `club_id NULL`.

- [x] **G4-14. Визуальное сравнение журнала.** Без фильтра журнал содержит записи входа самого инструмента (время и IP
  входа в новом — реальные, V-5), поэтому страница снимается с фильтром `event=cash.income`. Порядок ключей
  подробностей: в новом — порядок jsonb (по длине ключа, затем по байтам — так же сортирует JSON-колонка MySQL в
  проде старого), в копии старого для сравнения (sqlite) — порядок вставки. Это даёт 0,61 % на desktop (порог страницы
  1 % с объяснением) и ~8 % на mobile (перенос строк в узкой колонке меняет высоту строк) — мобильный вид оставлен
  `pending` (`activity-logs-mobile`). Разметка и данные совпадают.

# Этап 3, G5 — настройки клуба и «API и интеграции»: вопросы и принятые решения

Владелец поручил решать самостоятельно по принципам `docs/DECISIONS.md`; ниже — решение и обоснование.
Экраны: `settings/club.blade.php`, `languages.blade.php`, `finances.blade.php` (+ `percent-levels.blade.php`),
`guests.blade.php`, `integrations.blade.php`; `api.blade.php` не переносится (Q-059); `permissions*` — G3.
REST: `api/settings.yaml` (раздел `settings`), `api/integrations.yaml` (раздел `integrations`), флаг
`club.can_manage_integrations` в `/api/auth/me` (`api/auth.yaml`). Миграция `0019_club_images.sql`.

- [x] **S-1. Где хранить логотип и картинку экрана входа.** В старом — локальный диск Laravel. Новый сервер —
  несколько инстансов без общего диска; G4 для картинок новостей выбрал таблицу (`news_images`, 0018). Решение:
  так же — `club_images (club_id, kind logo|signin)`, ≤ 1 МБ / ≤ 3 МБ (CHECK), RLS. Пути в `clubs.logo_path` /
  `signin_image_path` прежнего формата (`club-logos/<club>/<40 символов>.png`), публичная отдача
  `GET /club-logos/{club}/{file}` и `/club-signin-images/{club}/{file}` с заголовками старого кода
  (`immutable`, `nosniff`, `CSP default-src 'none'`), имя файла сверяется с путём. Проверка — тип по содержимому
  (PNG/JPEG), размер, размеры в пикселях, как в старых правилах; тексты `mimes`/`dimensions` — английские тексты
  валидатора (в `ru.php` их нет — как в старом). Инструмент переноса должен скопировать файлы с диска в таблицу.

- [x] **S-2. Карточка «Ключ установки клуба».** Постоянного ключа больше нет (Q-037, Q-050: коды регистрации и
  ключи образа — экран G1 `/club-computers/enrollment`). Карточка и якорь оставлены (вид меню и страницы),
  содержимое той же разметки (подпись, поле только для чтения с адресом `/club-computers/enrollment`, кнопка-ссылка
  «Открыть» при праве `club_map.view`, примечание) — высота карточки та же. Новые строки (ключи перевода): «ПК клуба
  подключаются по коду регистрации или ключу образа.», «Открыть», «Код регистрации действует один раз, ключ образа
  можно отозвать — на странице «Подключение ПК».» — переводов kk/en пока нет (добавить в суперадминке). На визуальном
  сравнении карточка `#club-key` замаскирована (в старом там случайный ключ).

- [x] **S-3. Q-002 для порогов уровней.** Пороги накопительной скидки и бонуса — суммы в тенге; старый код округлял их
  до 0,01 (`PercentLevels::normalize`). Решение Q-002: больше 2 знаков после точки — 422 (`decimal`), проценты —
  как в старом (округление до 0,01). Сохраняются в формате v2 (Q-003, `bonus.EncodeLevels`); при сравнении «было →
  стало» уровни сравниваются по значению (v1 в базе и те же уровни v2 — не изменение).

- [x] **S-4. Пункт меню «API» (`/settings/api`).** Экран не переносится (Q-059). Пункт оставлен ради вида меню;
  маршрут перенаправляет на «API и интеграции» (если есть доступ) или на «Настройка клуба».

- [x] **S-5. Журнал доставок вебхуков.** В старом — 20 последних. Решение (CLAUDE.md: растущие списки — keyset):
  первые 20 и кнопка «Показать ещё» (`GET /api/settings/integrations/deliveries?cursor=`), индекс
  `webhook_deliveries (club_id, id)` (0019). Пока доставок ≤ 20, вид как в старом.

- [x] **S-6. Блокировка строки клуба.** Старый `save()` перезаписывал весь JSON без блокировки (параллельные
  сохранения разных секций теряли изменения). Сейчас — `SELECT … FOR UPDATE` строки клуба в транзакции.

- [x] **S-7. Аудит.** `settings.updated` секции «Финансы» (бонусы, скидки, оплата времени) — `audit_log` категории
  `settings` (было/стало по изменённым полям). Ключи API (создание, перевыпуск, отзыв) — `security` (без секрета),
  `integrations.permission_changed` — `permission`. Журнал действий — как в старом; слова «да»/«нет» в деталях
  `settings.updated` — русские (ключи, W-3).

- [x] **S-8. ConfigChanged агентам.** После сохранения секций, пояса, языка, PIN, времени обслуживания, логотипа и
  картинки входа — команда `ConfigChanged` всем ПК клуба в сети (`httpx.Deps.ClubConfigChanged`,
  `server/internal/app/club_config.go`; конфигурация собирается один раз на клуб, рассылка в фоне). ПК не в сети
  получат конфигурацию в Welcome.

- [x] **S-9. Язык и пояс в Me.** `/api/auth/me` читает клуб из БД на каждый запрос; кэш языка текстов ответов
  (`i18n.Catalog.ClubLocale`, 30 с) сбрасывается на этом инстансе (`ForgetClubLocale`), другие инстансы — до 30 с.
  Фронт после смены языка/пояса перечитывает Me (`session.reloadMe()`), интерфейс переключается сразу. Сообщение
  «Язык интерфейса изменён.» — уже на новом языке (как `LocaleResolver::apply()` в старом).

- [x] **S-10. timezone:all.** Список поясов PHP 8.4 (`DateTimeZone::listIdentifiers()`, база 2026.5) вшит в сервер
  (`zones_list.go`), проверка — строго по нему (устаревшие имена вроде `Europe/Kiev` отклоняются, как в старом);
  смещения — по `time/tzdata`, встроенной в бинарник (не зависит от ОС).

- [x] **S-11. PIN выхода.** Хэш — Argon2id (`password.Hasher`), старые bcrypt проверяются агентским API (Q-S6).
  Дата «PIN задан» показывается в поясе клуба (в старом — в поясе приложения).

- [x] **S-12. Секрет вебхука в БД.** `webhook_endpoints.secret` хранится как есть (его читает `webhook.Deliverer` для
  подписи); шифрование ключом `ZAFIRO_ENCRYPTION_KEY` (Q-050) — отдельная задача для раздела вебхуков (Этап 4),
  в журнал и аудит секрет не пишется. Кэша метаданных API-ключей в Go пока нет (API v1 — Этап 4), сбрасывать нечего.

- [x] **S-13. Лимиты API-ключей.** `default/max_rate_limit_per_minute` (120/1000) — значения по умолчанию старого
  конфига, константы раздела; когда появится конфигурация API v1 (Этап 4) — брать из неё.

- [x] **S-14. Ошибки полей секции «Настройка клуба».** В старом шаблоне ошибок полей секции `club` нет (видны только
  ограничения браузера) — перенесено так же; сервер отвечает 422 с ошибками.

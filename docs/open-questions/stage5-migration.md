# Этап 5 — перенос данных: решения и открытые вопросы

Решения приняты по принципам `docs/DECISIONS.md` (владелец поручил). Описание инструмента —
`tools/migrate-from-mysql/README.md`; код — `server/cmd/migrate-from-mysql`, `server/internal/migrate`.

## M1. Ядро переноса

### Решено

- [x] **S5-M1-1. `apply` — одна транзакция Postgres на клуб, без шагов с возобновлением.**
  Клуб заморожен в Laravel, объём одного клуба (тысячи клиентов, журнал за годы) Postgres проводит одной транзакцией;
  зато нет частичных состояний: ошибка, блокер в данных или расхождение сверки — откат, повтор начинается с чистого
  листа. Шаги с возобновлением требовали бы таблицы состояния переноса и идемпотентной дозаписи каждой таблицы —
  а ledger только дополняется (0002), так что «доделать» половину денег безопасно нельзя. Партиции журналов
  создаются до транзакции (`db.EnsurePartitions`, DDL идемпотентен; лишние пустые партиции безвредны).
  Сверка (`verify`) выполняется **внутри** транзакции до коммита (README старого плана: «при расхождении — откат»).
  Чтение MySQL — один снимок `REPEATABLE READ … CONSISTENT SNAPSHOT`, общий для чтения, записи и сверки.
- [x] **S5-M1-2. Повторный `apply` перенесённого клуба — отказ без изменений** (код выхода 5), а не идемпотентное
  обновление. После коммита клуб живёт в zafirogo (новые операции, ledger только дополняется), «обновить из MySQL»
  значило бы затереть его новые данные. Проверка — до транзакции и ещё раз под advisory-блокировкой переносов.
  Интеграционный тест сравнивает отпечаток данных до и после повторного запуска.
- [x] **S5-M1-3. Последовательности id (уточнение Q-029).** id сохраняются; последовательность каждой таблицы старой
  схемы (ядро и таблицы M2) ставится **не ниже `max(id во всей MySQL) + 10⁹`** (флаг `--id-reserve`), а не выше
  максимального id переносимого клуба: Laravel продолжает выдавать id остальным клубам, и строка, созданная в zafirogo
  с id «max клуба + 1», столкнулась бы с id клуба, переносимого позже (риск §3.10 `docs/schema-changes.md`).
  Запас 10⁹ — из рекомендации Q-029; значение только растёт (повторные переносы его не уменьшают).
  `mobile_api_tokens` (с 10¹²) не трогаем. Тест: новая запись журнала после переноса получает id > max MySQL + запас.
- [x] **S5-M1-4. Общие аккаунты (`users`).** Переносятся участники клуба и все аккаунты, на которые ссылаются строки
  клуба (автор новости, сотрудник смены, клиент брони…), — набор строится из ссылок (`UserRefs` в `spec.go`).
  Аккаунт с тем же id уже в zafirogo (перенесён с другим клубом) — не дублируется и **не перезаписывается**: после
  первого переноса источник правды — zafirogo (смена пароля/имени там не должна откатиться); отличия — в отчёте
  (`user_kept`). Тот же id с другим телефоном или телефон, занятый другим id (аккаунт, созданный в zafirogo), —
  блокер: нужно ручное слияние. Ссылка на несуществующий аккаунт — блокер.
- [x] **S5-M1-5. `member_balances.id` не сохраняется.** Роль `zafiro_platform` может вставлять в `member_balances` только
  `club_id, user_id, created_at, updated_at` (0004, баланс меняет только ledger); id строки баланса нигде не
  используется (ключ — `club_id, user_id`). Остатки — `billing.MigrateOpeningBalance`.
- [x] **S5-M1-6. Время.** `config/app.php` старого проекта — `'timezone' => 'UTC'` (~74, не из env), в
  `config/database.php` у соединения нет `timezone` — Laravel пишет строки UTC, сессия MySQL в поясе сервера.
  Инструмент читает так же (пояс сессии не меняет: `TIMESTAMP` вернёт ту же строку, что записал Laravel) и трактует
  строки в `--source-tz` (по умолчанию UTC). В отчёте — `@@global.time_zone`, `@@session.time_zone`,
  `@@system_time_zone`. Риск: если пояс сервера MySQL менялся между записью и переносом, `TIMESTAMP`-колонки
  сдвинутся — проверить на копии прода (см. открытые вопросы).
- [x] **S5-M1-7. Значения вне CHECK (Q-026) — блокер**, без автоматической замены: CHECK-списки читаются из
  `pg_constraint` (не дублируются в коде), неизвестное значение исправляется в источнике по одному (рекомендация Q-026).
- [x] **S5-M1-8. `created_at = NULL` (Q-030).** В партиционированных журналах (`activity_logs`, `api_request_logs`)
  ключ партиции обязателен — `COALESCE(created_at, updated_at, момент переноса)`, как миграция 0011; в остальных
  таблицах NULL переносится как есть, всё — в отчёт. `NOT NULL DEFAULT now()` — отдельной миграцией после переноса
  всех клубов (иначе следующий клуб с NULL не перенесётся).
- [x] **S5-M1-9. Настройки (Q-022, Q-023, BQ-3) в M1 — только отчёт**, запись как есть (v1): новый сервер читает
  старые значения так же, как `SettingsController::minutes()` (`internal/http/sections/settings/values.go`).
  Нормализация («30 сек» → число, черновые ключи) и уровни v2 — одним проходом в M2 (Q-003). Клуб `legacy` без
  `settings`: `--legacy-settings storage/app/settings.json` подставляет файл, без файла — дефолты (предупреждение).
- [x] **S5-M1-10. Не переносятся ядром:** `agent_qr_logins` (одноразовые QR, живут минуты; агенты переустанавливаются),
  `transfer_codes`, `password_recovery_codes` (Q-051), `server_metrics`, `request_metrics` (Q-083),
  `api_keys`/`api_idempotency_keys`/`webhook_endpoints`/`webhook_deliveries` (M2: секреты APP_KEY, Q-050),
  `api_request_logs` старше срока хранения. `club_request_metrics`, `club_load_snapshots` — переносятся (Q-083
  «по желанию», это данные клуба). `platform_logs` — только события с `club_id` клуба; платформенные таблицы и
  события без клуба — отдельный платформенный шаг.
- [x] **S5-M1-11. Касса в ledger.** Входящий остаток `cash_drawer` (`migration_opening_balance`, ключ
  `opening_cash_drawer`, встречный счёт `opening_balance`): остаток открытой смены (opening + приходы − расходы),
  а без открытой смены — `closing_balance` последней закрытой. Без этого первое закрытие смены в zafirogo записало бы
  снимок кассы без перенесённого остатка (CSQ-7); выравнивание при открытии следующей смены (CSQ-1) исправило бы это,
  но одной большой «разницей».
- [x] **S5-M1-12. Минуты пакетов** — входящий остаток в ledger минут (`opening_minutes:<id>`), чтобы сумма движений
  пакета сходилась с `minutes_left`; если владелец пакета не участник клуба (FK ledger минут), пакет переносится,
  а остаток в ledger не пишется (предупреждение).
- [x] **S5-M1-13. Ключ установки клуба** (`clubs.installation_key*`) не переносится — по Q-050 выпускается заново.
  Хэши `club_computers.agent_token_hash`, `club_invitations.token_hash`, PIN `agent_exit_pin_hash` — как есть
  (Q-051; судьба старых токенов агентов — M2).
- [x] **S5-M1-14. Slug клуба, совпадающий без учёта регистра со slug клуба zafirogo (Q-025), — блокер**: в MySQL
  (`utf8mb4_unicode_ci`) это был бы один клуб. Внутри одного клуба дублей без учёта регистра быть не может — их
  не пропустили бы уникальные индексы MySQL с той же сортировкой.
- [x] **S5-M1-15. Роль Postgres.** Логин — владелец схемы с членством в `zafiro_platform` (PD-9): данные пишутся под
  `SET LOCAL ROLE zafiro_platform` (RLS-политики платформы, права на `member_balances` как у сервера), `setval` и
  партиции — исходной ролью. `app.club_id` клуба ставится тоже (ledger проверяет тенант транзакции). Строки
  подключения — из окружения, не из аргументов.
- [x] **S5-M1-16. Источник тестов — настоящая схема.** `tools/migrate-from-mysql/dump-schema.sh`: копия старого
  проекта, `php artisan migrate:fresh` в `mysql:8.4.13` (php 8.4 + `pdo_mysql`, собирается из исходников образа без
  сети), демо-данные — старый сидер `tools/visual/old/seed.php` (он писал в sqlite, с MySQL работает без правок;
  кассовые операции — сервисом старого кода). Дамп `--no-data` и данные — в `testdata`, тесты PHP не запускают.
  `translations` в дамп не входят (платформенные, ~7 тыс. строк).
- [x] **S5-M1-17. Новая зависимость** `github.com/go-sql-driver/mysql v1.10.1` (02.09.2026, старше 14 дней — PD-4) и её
  `filippo.io/edwards25519 v1.2.0`. `govulncheck` в этой среде недоступен (vuln.go.dev закрыт прокси, Q-079).

### Открыто

- [ ] **S5-M1-О1. Пояс сервера MySQL в проде.** Проверить на копии прода `@@global.time_zone` и что он не менялся
  (иначе `TIMESTAMP`-колонки при чтении сдвинутся, а `DATETIME` — нет). Отчёт `plan` печатает пояса; при
  `time_zone ≠ SYSTEM/UTC` сверить выборочные строки с журналом Laravel.
- [ ] **S5-M1-О2. Аккаунт, зарегистрированный в zafirogo, с телефоном клиента ещё не перенесённого клуба** даёт
  блокер `user` — нужна процедура ручного слияния (какой id оставить, перенос ссылок). Пока не встречалось.
- [ ] **S5-M1-О3. Время транзакции.** Для клуба с миллионами строк `activity_logs` транзакция будет долгой
  (вставка пачками по 2000 строк через `unnest`); замерить на копии прода и при необходимости поднять `--batch-size`.

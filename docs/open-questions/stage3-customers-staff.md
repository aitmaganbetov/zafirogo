# Этап 3, G3 — клиенты, сотрудники, приглашения, права: вопросы и принятые решения

Владелец поручил решать самостоятельно по принципам `docs/DECISIONS.md`; ниже — решение и обоснование.
Экраны: `users.blade.php`, `users-password.blade.php`, `workers/index.blade.php`, `settings/permissions.blade.php`,
`settings/permissions-edit.blade.php` (`docs/parts/10-screens.md`, раздел 2.1 и «Настройки»).
REST: `api/customers.yaml` (дополнен), `api/staff.yaml` (новый раздел `staff`).

- [x] **G3-1. Поиск клиентов в интерфейсе.** В старом экране «Пользователи» поля поиска нет (только `paginate(25)`).
  API ищет по имени/телефону (`?q=`, решение RQ-12). Решение: видимого поля не добавляем (принцип 3 «новые функции не
  добавляются», визуальное совпадение); страница понимает `/users?q=…` (ссылка из других экранов, напр. кассы — Q-070),
  пагинация сохраняет `q`. Если владелец захочет поле — одна строка разметки в шапке.

- [x] **G3-2. Пагинация — keyset вместо номеров страниц.** CLAUDE.md: «списки, которые растут, — keyset». Номера
  страниц keyset не даёт, поэтому вместо `$users->links()` (номера) — вид Laravel `simple-tailwind.blade.php`
  («« Назад / Вперёд »», `web/src/components/SimplePagination.tsx`, разметка и классы один-в-один). Адреса:
  `/users?after=<user_id>` / `?before=<user_id>`, `/workers?cursor=…` / `?before=…`. «Всего: :count» — отдельный
  `COUNT` (тот же фильтр). На демо-данных (одна страница) расхождения нет: пагинация не показывается, как и в старом.

- [x] **G3-3. «Карточка клиента» (балансы, история ledger, лояльность).** В старой админке отдельной карточки клиента
  нет: балансы, скидка (персональная или накопительная — «накопительная») и «Потрачено» — в строке списка; историю
  баланса показывал только агент (`GuestHistory`). Решение (принцип 3): отдельный экран не добавляем; строка списка
  показывает лояльность как в старом (`discount_effective`, `discount_cumulative` считает сервер — `LoyaltyProgram::
  percentFor()`), эндпоинты `GET /api/customers/{id}` и `/ledger` (Этап 2) остаются для будущего экрана истории
  (RQ-12) и других клиентов API.

- [x] **G3-4. Создание клиента — одна транзакция с начальным балансом (RQ-13).** `POST /api/customers` создаёт
  пользователя, членство, строку баланса и операцию ledger `initial_balance` (`billing.SetInitialBalance`) атомарно,
  как `DB::transaction` в `UserController::store()`; заголовок `Idempotency-Key` обязателен (деньги). Отдельный
  `POST …/initial-balance` (Этап 2) оставлен. Телефон — `PhoneNumber::normalize()` (Q-033: ведущая 8 тоже
  отрезается; `StoreUserRequest` старого отрезал только 7). Гонка двух созданий одного номера — 422 unique, а не 500.

- [x] **G3-5. Изменение клиента и пополнение без кассы — одна транзакция.** Старый `update()` менял имя/email/скидку и
  пополнял/списывал баланс в одном `DB::transaction`: ошибка «На балансе клиента меньше суммы списания» откатывала и
  имя. `PATCH /api/customers/{id}` делает так же (`Idempotency-Key` обязателен, только если есть сумма); прежний
  `POST …/balance-adjustments` оставлен и использует тот же код. Тексты журнала (`user.balance_*`) теперь на языке клуба
  через каталог (`d.T`), как `__()` старого.

- [x] **G3-6. Ошибки формы «Изменить клиента».** В старом шаблоне ошибки показывались только в диалоге «Новый
  клиент» (`data-open-on-load` открывал **его** даже при ошибке изменения) — ошибка изменения появлялась в чужом
  диалоге. Решение: ошибка показывается в диалоге изменения тем же блоком (классы те же). Отличие видно только при
  ошибке.

- [x] **G3-7. Сброс пароля: где показать пароль.** Старый ответ `POST /users/{id}/password` — страница с паролем
  (`no-store`). В SPA пароль приходит в JSON (`Cache-Control: no-store, private`) и держится только в памяти вкладки
  до показа страницы `/users/{id}/password` (не в URL, `history.state`, `sessionStorage`); перезагрузка — к списку.
  `$user->tokens()->delete()` → отзыв токенов гостя в Valkey и `SignOutGuest` на ПК (`httpx.Deps.SignOutGuest`,
  `server/internal/app/guest_signout.go`); запись аудита `security / user.password_reset`. Ошибка 429 (20/мин) —
  красным блоком над списком (в старом — страница ошибки Laravel).

- [x] **G3-8. Ссылка-приглашение терялась.** `ClubInvitationController::store()` делал `redirect()->route('users.index')
  ->with('invite_url', …)`, а `users.blade.php` `invite_url` не выводит (выводит только `workers/index`): ссылка
  создавалась, но не показывалась (токен хранится только хешем — восстановить нельзя). Решение (принцип 2: функция
  не работала): SPA остаётся на «Работниках» и показывает поле со ссылкой и «Копировать ссылку» (разметка
  `workers/index`). Сервер отдаёт путь `/invitations/{token}`, адрес сайта добавляет клиент (без доверия к `Host`).

- [x] **G3-9. Удаление сотрудника — отзыв сессий.** В старом бывший сотрудник оставался вошедшим, но страницы
  отвечали 403 по роли. Решение (принцип 4): после коммита `RevokeUser` (все сессии панели пользователя — сессии в
  Valkey не делятся по клубам; если он сотрудник другого клуба, войдёт заново). Смена роли и прав — без отзыва: права
  REST читаются из БД на каждом запросе, событие `staff.access_changed` закрывает WebSocket сотрудника (4001), а
  клиент после переподключения перечитывает `/api/auth/me` (одна строка в `web/src/realtime/hooks.ts`) — меню и гарды
  обновляются без перезахода.

- [x] **G3-10. Аудит прав.** `audit_log` (категория `permission`): `worker.added`, `worker.role_changed`,
  `worker.removed`, `invitation.created` (без email и токена — только роль и срок), `permissions.updated` (до/после —
  карты выбора владельца). Журнал действий (`activity_logs`) — как в старом (тексты на языке клуба).

- [x] **G3-11. «API и интеграции» в меню настроек.** `@can('manage-integrations')` — владелец или
  `club_memberships.can_manage_integrations`; флага нет в `/api/auth/me`. Пока пункт виден только владельцу.
  Рекомендация группе 5 (настройки/интеграции): добавить флаг в `Me` и условие в `SettingsLayout`.

- [x] **G3-12. Общие компоненты.** `web/src/components/SettingsLayout.tsx` — перенос `settings/layout.blade.php`
  (меню, заголовок, `status`; форму `settings-content` и якоря `settings.anchors` страница передаёт сама — для
  группы 5). `web/src/components/SimplePagination.tsx` — `simple-tailwind.blade.php`.

- [x] **G3-13. Режим просмотра суперадмина.** Кнопки изменения (добавить/изменить/сбросить пароль, формы работников,
  смена роли, «Убрать», сохранение прав) скрыты или неактивны при `me.read_only` (web/README); сервер всё равно
  отвечает 403 `read_only`. Страница «Права» (club-role:owner,admin) проверяет роль в обработчике (операции `Public`
  в `httpx.Access`), включая запрет записи в режиме просмотра.

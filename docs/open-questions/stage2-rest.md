# Вопросы Этапа 2 — блок B1 «REST API админки»

Код: `server/internal/http/{admin,cash,warehouse,customers,sessions}.go`, `api/openapi.yaml`,
`db/queries/admin_*.sql`, журнал и события сервисов — `server/internal/{billing,cash}/service/events.go`.

- [ ] **RQ-1. Тексты ошибок правил форм.** Для правил FormRequest (`required`, `gt`, `in`, `max`…) отдаются английские
  тексты валидатора Laravel по умолчанию (`The amount field must be greater than 0.`) — так их видел старый код до
  перевода; русский/казахский — в каталоге переводов по этим ключам. Все ошибки полей сразу (как FormRequest) —
  только у формы пополнения (GS-013); остальные формы отдают первую ошибку. Рекомендация: так оставить, при переносе
  экранов — общий валидатор на все поля.
- [ ] **RQ-2. Идемпотентность денежных POST на HTTP.** Ключ `Idempotency-Key` обязателен (CSQ-4: SPA генерирует UUID);
  ответ первого выполнения хранится в `billing_requests` (операция `http:<имя>`), повтор с тем же телом — тот же ответ
  и статус, с другим — 409. Внутри — вторая линия: ключ кассовой операции и ledger. Завершение сессии
  (`end-session`) идёт в собственной транзакции billing — ответ сохраняется отдельной транзакцией после неё
  (параллельный повтор получит 422 «На компьютере нет такой активной сессии.», а не тот же ответ). Нет заголовка —
  400 `idempotency_key_required` (раньше проверки входа, т.к. параметры разбирает сгенерированная обёртка).
- [ ] **RQ-3. Вебхуки `sale.completed`, `stock.changed`, `product.*` — в формате старого кода** (суммы строкой
  `"1500.00"`, `price/total` строк чека — float PHP), плюс новые поля `amount_tiyn`, `price_tiyn`, `total_tiyn`.
  Это противоречит «никогда float в JSON» (CLAUDE.md), но внешние интеграции ждут старый формат. Нужно решение
  владельца: (а) оставить совместимость + `*_tiyn`; (б) только тиыны (ломает интеграции).
- [ ] **RQ-4. `computer.state` от сервисов — частичный дифф.** Сервисы знают только сессию ПК (`session: {id, user_id,
  guest, ends_at}` или `null`, `status: busy`), но не связь с агентом; `online/offline` присылает присутствие (B0).
  Клиент сливает дифф по полям. Нужен единый формат с B0.
- [ ] **RQ-5. `cash.transaction.kind = guest_session`** — добавлен к каталогу `docs/realtime.md` (там нет вида для
  гостевой сессии). Обновить документ (не мой файл).
- [ ] **RQ-6. Пересадка сотрудником** (`POST /api/club-computers/{id}/transfer`, право `pc_control.update`, маршрут
  `club-computers.control`) — нового нет в старом коде (там только сам клиент). Пересаживается сессия клиента;
  гостевая сессия с кассы — ошибка «На этом ПК нет вашей оплаченной сессии.». Подтвердить, что функция нужна.
- [ ] **RQ-7. Nonce печати Z — отдельный `POST …/z-report/nonce`** (в старом его выдавал GET Z-отчёта в сессию).
  В режиме просмотра суперадмином nonce не выдаётся (POST запрещён). Неверный nonce — 419, как `abort(419)`.
- [ ] **RQ-8. `activity_logs.description` пишется по-русски** (ключ с подставленными значениями), как SV-10/EV-7:
  старый код писал результат `__()` на языке запроса.
- [ ] **RQ-9. `subject_type`** — морф-классы Laravel (`App\Models\CashTransaction`, …), как в перенесённых строках.
  A2 (`agent/enroll`) пишет `club_computer` — расхождение; договориться об одном формате.
- [ ] **RQ-10. Журнал без данных запроса не пишется.** `RecordActivity` пропускает запись, если в контексте нет
  `activity.RequestMeta` (фоновые задачи; старый код — тоже). gRPC агента должен ставить meta (IP пира), иначе покупки
  в агенте не попадут в журнал. HTTP ставит meta middleware `RequestMeta` роутера (W-5).
- [ ] **RQ-11. Карта клуба — неполный перенос `computerStates`:** нет `classes`/подсветки (строит фронт), текста
  `session_tariff` («Поминутно: :count мин.»), `agent_outdated` (нет `AgentUpdate`), `staff_kind`. Добавить при
  переносе экрана карты.
- [ ] **RQ-12. Клиенты:** список — keyset по `user_id` (как `orderBy('user_id')`) + новый поиск по имени/телефону;
  `staffElsewhere`, `loyalty` не отдаются. История баланса — проводки ledger с кодами операций (`top_up`,
  `session_refund`…), без заголовков `GuestHistory` («Возврат пополнения на кассе») — их строит экран истории.
- [ ] **RQ-13. Начальный баланс — отдельный эндпоинт** (`POST /api/customers/{id}/initial-balance`, право маршрута
  `users.store` + `customer_money.update`, один раз на клиента — ключ ledger `initial_balance:<id>`): создание клиента
  (`users.store`) в этот блок не входило.
- [ ] **RQ-14. Валюта в `BalanceChanged`** после корректировки владельцем — пустая строка (агент возьмёт валюту клуба);
  в кассе и покупках — `finances.currency`.

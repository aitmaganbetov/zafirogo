# Этап 3, G2 — касса, склад, заказы с ПК, услуги: вопросы и принятые решения

Владелец поручил решать самостоятельно по принципам `docs/DECISIONS.md`; ниже — решение и обоснование.
Экраны: `cash-register/*`, `warehouse.blade.php`, `stock/index.blade.php`, `shop-orders/index.blade.php`,
`services/index.blade.php`.

- [x] **G2-1. Nonce печати Z-отчёта — в Valkey (Q-015, CSQ-3, RQ-7).**
  - Сделано: `cash/service.ZNonceStore` — `ValkeyZNonces` (SET EX 1 ч + GETDEL, хранится только sha256 nonce),
    ключ — клуб, смена и **сотрудник** (как `session()->put("z_report_nonce.{id}")` старого кода: nonce одного
    сотрудника не годится другому). Без настройки (тесты) — `MemoryZNonces` в памяти процесса. Миграция 0016 удаляет
    `cash_shifts.z_report_nonce_hash`; флаг печати (`z_report_printed_at/by`) остаётся у смены (CSQ-3).
  - Nonce выдаётся при показе Z-отчёта открытой смены (`POST …/z-report/nonce`, как GET `zReport()` старого кода
    клал его в сессию), отметка — после `afterprint`. Кнопка «Закрыть смену» активна только после отметки на этой
    странице (как в старом: после перезагрузки страницы нужно напечатать снова).
  - Решение: так.

- [x] **G2-2. Витрина кассы и выбор пользователя (Q-070).** В старом `CashRegisterController::index()` клал в HTML
  **все** товары в наличии и **всех** пользователей клуба. Сейчас: `GET /api/cash/catalog` (число товаров для «Все»,
  5 категорий в порядке первого появления по имени — `ORDER BY min(name)`, активные услуги), `GET /api/cash/products`
  (страницы по 60, keyset по имени, фильтр категории — на сервере, подгрузка при прокрутке), `GET /api/cash/customers`
  (поиск по имени/телефону, 20 строк, задержка 250 мс — как поиск клиента в бронях). Разметка и классы — старые.
  - Отличие: при выбранной категории фильтрует сервер (в старом — `display:none` у уже загруженных карточек); для
    пользователя вид тот же.
  - Решение: так (Q-070).

- [x] **G2-3. «НДС 5% (включён)» (Q-019).** Расчёт — целыми тиынами: `cash.VATIncluded()` (Go) и
  `vatIncludedTiyn()` (TS) по одной формуле `round(T/100·5/105)` → тенге, общие векторы
  `server/internal/cash/testdata/vat.json` проверяют оба теста. Итог продажи — сумма операции с сервера (чек).
  - Решение: так.

- [x] **G2-4. Склад: выбор товара в формах «Движение товара» и «Удаление товара» (Q-070).** Вместо `<select>` со всеми
  товарами — поле поиска (`ProductPicker`, `GET /api/warehouse/products?q=`) с классами старого select и списком
  `pos-user-options` (как в бронях); по умолчанию выбран первый товар по имени, как у select.
  - Отличие на снимке: у поля нет стрелки select.
  - Решение: так (Q-070), расхождение — в отчёте визуального сравнения.

- [x] **G2-5. Пагинация экранов — номер страницы (`?page=`), а не keyset.** Экраны используют вид
  `$paginator->links()` (номера страниц, «Showing 1 to 25 of N»), которому нужны `total` и номер страницы.
  Списки клубные и короткие (операции одной смены, товары, услуги, заказы с фильтром по статусу; индексы
  `(club_id, status, id)`, `(club_id, name)`, `(club_id, category, name)` — 0016). Добавлен параметр `page` и поля
  `total`/`per_page` в `listCashOperations`, `listProducts`; новые `listStock`, `listShopOrders`, `listServices` —
  по номеру страницы. Keyset `before_id`/`cursor` прежних эндпоинтов сохранён (для API и приложений).
  - Решение: так (принцип 2 — тот же вид); keyset — где нет нумерованных ссылок (витрина кассы, поиск).

- [x] **G2-6. Отмена заказа из агента: клиент без строки баланса.** `AgentShop::cancel()` при отсутствии
  `member_balances` клиента деньги не возвращал (терялись). Как решение Q-012: строка создаётся (нулевая) и сумма
  зачисляется проводкой `shop_order_cancel` (ключ `shop_order_cancel:<id>`), траты лояльности уменьшаются
  (`LoyaltyProgram::subtractSpending`). Повтор запроса с тем же `Idempotency-Key` — тот же ответ.
  - Решение: так (принцип 2: исправление потери денег).

- [x] **G2-7. Последние движения склада с удалённым товаром.** В старом `$movement->product->name` для удалённого
  (SoftDelete) товара — ошибка страницы (500). Сейчас имя удалённого товара показывается.
  - Решение: так (принцип 2: явный баг, страница не открывалась).

- [x] **G2-8. Опрос заказов → WebSocket (Q-062).** `GET /shop-orders/state` раз в 15 с с `location.reload()` заменён
  событиями `shop_order.created` (заказ из агента) и `shop_order.updated` (выдан/отменён — новое событие, `new_count`
  для бейджа): страница перечитывает список. Эндпоинт `GET /api/shop-orders/state` оставлен (маршрут старого кода).
  - Решение: так.

- [x] **G2-9. Тексты статусов после действий.** Статусы с подстановками («Заказ №:id выдан.», «Товар «:product»
  удалён.», «Услуга «:service» добавлена.») собирает фронт из ключа и параметров (`t()`); тексты операций кассы
  («Продажа проведена…», «Возврат проведён: …») — сервер на языке клуба (`h.d.T`, F1-5).
  - Решение: так.

- [x] **G2-10. Режим просмотра суперадмина.** Кнопки изменения на экранах раздела неактивны при `me.read_only`
  (сервер всё равно отвечает 403 `read_only`). Nonce печати Z в режиме просмотра не запрашивается (POST запрещён).
  - Решение: так.

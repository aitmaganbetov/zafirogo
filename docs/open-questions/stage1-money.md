# Вопросы Этапа 1: пакет `money`

Пакет: `server/internal/money`. Оракул: `tools/php-oracle/gen-round-fixture.php` (README там же, раздел «round()»).

- [ ] **MQ-1. Какая версия PHP в проде старого Laravel (8.3 или 8.4+)? От неё зависит, сколько тиынов дают формулы `(int) round($x * 100)`.**
  - Контекст: `composer.json` старого проекта требует `"php": "^8.3"`, то есть допускает 8.4 и 8.5. Локально стоит 8.3.6,
    фикстура и `money.PHPRound` повторяют **8.3** (`ext/standard/math.c` `_php_math_round()` с предокруглением до 15 значащих цифр).
    В PHP 8.4 `round()` переписан (предокругления нет, вместо него проверка «значение уже ровно x.5 в десятичной записи»).
  - Проверено: тот же набор из 310 438 кейсов прогнан на PHP 8.4.27 (`php:8.4-cli-alpine`). Для `round($x, 2)` с суммой
    `x.xx5` (категории `x.xx5`, `big x.xx5`, `a*b/100`) ответы 8.3 и 8.4 **совпадают**. Расходятся формулы вида `round($x * 100)`:
    в категории `x.xx5 * 100` разный ответ у 1 147 из 25 000 сумм (4,6 %), у крупных сумм — 452 из 10 000. Примеры:
    `round(0.145 * 100)`: 8.3 → 15, 8.4 → 14; `round(1.005 * 100)`: 8.3 → 101, 8.4 → 100; `round(0.49999999999999994)`: 8.3 → 1, 8.4 → 0.
  - Где это в старом коде: `app/Services/TopUpBonus.php` `TopUpBonus::for()` (`$cents = (int) round($amount * 100)`, процент
    `(int) round($percent * 100)`), `app/Services/Friends.php` `storedCents()`, `AgentTariffPurchaseService::discounted()`
    (`(int) round($percent * 100)`), `app/Support/PercentLevels.php` (`(int) round($level[...] * 100)`). Входы — decimal из БД
    (максимум 2 знака), а у них `x*100` почти всегда целое во float с ошибкой < 1e-9, поэтому на реальных данных 8.3 и 8.4,
    скорее всего, совпадают; расхождение возникает на значениях с полутиыном (касса принимает `numeric` без ограничения знаков, BR-053).
  - Варианты: (а) прод на 8.3 — оставляем как есть; (б) прод на 8.4+ — добавить в `money` вариант `PHPRound84` и снять фикстуру на 8.4;
    (в) клубы на разных версиях — выбрать одну, указать в `docs/business-rules.md` §2.
  - Рекомендация: узнать `php -v` на сервере (`/home/admzafiro/Zafiro`, CLAUDE.md старого проекта) и в CI; пока — допущение **8.3**.

- [ ] **MQ-2. В `docs/business-rules.md` BR-001 неверный пример про наивный Go.**
  - Там написано, что `math.Round(x*100)` даст `1234 / 10000 / 100 / 267` для `12.345, 100.005*100, 1.005*100, 2.675`.
    Проверено (Go 1.24, PHP 8.3.6): `12.345*100 = 1234.5`, `100.005*100 = 10000.5`, `2.675*100 = 267.5` ровно во float64,
    поэтому наивный вариант случайно даёт **те же** 1235 / 10001 / 268. Ошибается только `1.005*100 = 100.49999999999999` → 100 (PHP: 101).
    Показательные примеры для сумм: `0.145 → 15` (наивно 14), `0.285 → 29` (28), `1.005 → 101` (100) — теперь в тестах `money`.
  - Ловушка: в Go константное выражение `100.005 * 100` вычисляется **точно** (без float64), поэтому в тестах множители надо
    передавать переменными (в `money_test.go` — `mul()` с `//go:noinline`).
  - Рекомендация: поправить пример в BR-001 (владелец документа — агент правил).

- [ ] **MQ-3. Касса: что именно MySQL получал от PHP-float.**
  - Проверено на `mysql:8.4.13` (strict mode): строка в `decimal(12,2)` округляется половиной от нуля по десятичной записи
    (`'1.005' → 1.01`, `'-1.005' → -1.01`, `'12.999' → 13.00`, `' 7.125 ' → 7.13`, `'1.5e2' → 150.00`); `'1,5'`, `'abc'`, `''`,
    `'0x1A'`, `'1.5x'`, `'1e400'` — ошибка 1366; выход за `decimal(12,2)` (`'9999999999.995'`, `'123456789012.34'`) — ошибка 1264.
    `d + 1.005` и `d + '1.005'` дают одинаковые 1.01 (и `2.675 → 2.68`). Таблица — `TestParseTengeRoundedMySQL`.
  - PHP-float уходит в SQL строкой `(string)$float` с `precision = 14` (Eloquent `increment()` вставляет число в SQL,
    PDO-параметры — `PARAM_STR`). Для этого есть `money.FromTengeFloatDecimal` = `ParseTengeRounded(PHPFloatString(f))`.
    Не проверено на живом Laravel (vendor в `../Zafiro` не установлен): точный путь `increment()`/каста `decimal:2` в версии
    Laravel старого проекта — пусть подтвердит агент кассы оракулом `tools/php-oracle` (Pest в копии Zafiro).
  - Рекомендация: в кассе для ввода пользователя — `ParseTengeRounded(строка запроса)`; для сумм, которые PHP считал во float
    (`$total += (float)$price * $qty`) — повторять float-формулу и `FromTengeFloatDecimal`.

- [ ] **MQ-4. Граница `MaxAmount = 1e15` тиынов (10 трлн ₸).**
  - Больше любого `decimal(14,2)` старой схемы (≈ 1e14 тиынов), меньше 2^53 (суммы точно представимы во float64).
    `ParseTenge*` возвращают `ErrOutOfRange` выше неё, `Add`/`Sub`/`MulDivRound` проверяют переполнение int64.
    Пределы конкретных колонок (`decimal(12,2)` = 999 999 999 999 тиынов) пакет не проверяет — это валидация места вызова.
  - Рекомендация: оставить; если владелец хочет повторить ошибку MySQL 1264 буквально — проверка на уровне формы/сервиса.

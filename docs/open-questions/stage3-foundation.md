# Этап 3, F1 — каркас SPA: вопросы и принятые решения

Владелец поручил решать самостоятельно по принципам `docs/DECISIONS.md`; ниже — решение и обоснование.
Конвенции для агентов экранов — `api/README.md`, `web/README.md`.

- [x] **F1-1. Разбиение REST по разделам.** Один `api/openapi.yaml` (37 операций) разнесён на `api/common.yaml`
  (Error, ValidationError, общие ответы и параметры) и `api/<раздел>.yaml`; каждый раздел — свой пакет
  `server/internal/http/api/<раздел>` (`<раздел>api`) и свой пакет обработчиков `server/internal/http/sections/<раздел>`,
  реестр — `server/internal/http/sections.go`. Генерация — `api/gen.sh` (конфиги oapi-codegen строятся на лету:
  новый раздел не требует конфига), фронт — `web/scripts/gen-api.mjs` → `web/src/api/gen/<раздел>.d.ts` (файл на
  раздел — без общих конфликтов). Права операций — `httpx.Access` (операция → маршрут Laravel → право), тест
  `access_test.go` в каждом разделе. Ответы с `common.yaml#/components/responses/*` работают через import-mapping.
  - Решение: так. Раздел `map` переименован в `clubmap` (имя пакета Go не может быть ключевым словом).
  - Операции суперадмин-просмотра (`/api/superadmin/clubs/{id}/view`, `leave-club`) оставлены в `auth`: они меняют
    сессию. Остальная суперадминка — свой раздел группы 6.

- [x] **F1-2. WebSocket: как браузер авторизуется (EV-3).** Решение EV-3 — cookie, «если нельзя — одноразовый тикет на
  30 с». Access-токен в памяти SPA (не cookie), поэтому — тикет: `POST /api/ws-ticket` (вход + клуб) →
  `GET /ws?ticket=…`. Тикет одноразовый (Valkey GETDEL), 30 с. В Valkey лежит не access-токен, а его шифротекст
  AES-GCM с ключом, выведенным из тикета (ключ записи — тоже хеш тикета): значение в кэше без тикета бесполезно
  (правило «секреты не в кэше»). На `/ws` Principal строится заново по токену (блокировка и права — как в REST).
  Код: `server/internal/http/wsticket`, `wsTicketAuth` в `server.go`, клиент — `web/src/realtime/client.ts`.
  Query-параметр не попадает в журнал (RequestLogger пишет путь без query).

- [x] **F1-3. Хранение переводов и конвертация (Q-065).** В `translations` строки — в формате Laravel (`:name`,
  `a|b|c`), как в старом проекте и в редакторе суперадминки; агент (gRPC) получает их как раньше. Конвертация в
  формат i18next — при выдаче `GET /api/i18n/{locale}` (`server/internal/i18n`): ключи **и** тексты `:name` →
  `{{name}}`; строка `trans_choice` (есть `|` и `:count`) даёт ещё ключи `<ключ>_one/_few/_many/_other` с формой,
  которую выбрал бы Laravel (`MessageSelector::getPluralIndex`, нет формы — первая). Группы `pagination` и
  `validation` отдаются как `группа.ключ` (`t('pagination.next')`). ETag — хеш пакета; пакет в памяти процесса,
  перестраивается при смене версии (max(updated_at) + число строк).
  - Импорт файлов `database/translations/{ru,kk,en}.php`: `go run ./cmd/import-translations -dir … -dsn …`
    (как `translations:sync`: вставляет отсутствующие строки, отредактированные не трогает; языки ru/kk/en
    создаёт, если их нет). Для переноса клуба таблицы `languages/translations` копирует `tools/migrate-from-mysql`
    (строки уже в формате Laravel — конвертация не нужна).
  - Риск: `:слово` в тексте, не являющееся подстановкой (одна строка суперадминки «подстановки (:name и т. п.)»),
    станет `{{name}}` и покажется буквально, если не передать параметр. Решение: принять; при переносе экрана
    «Языки и переводы» передать `{ name: ':name' }` или ключ без конвертации (группа 6).

- [x] **F1-4. Язык интерфейса.** Как `LocaleResolver`: вошедший — язык клуба (`me.club.locale`, по умолчанию `ru`),
  гость — язык браузера среди включённых, иначе `en`. Переключателя в шапке в старом не было (язык меняется в
  «Настройки → Языки», группа 5) — не добавляем (принцип 3). `me.club` дополнен полями `locale`, `timezone`, `Me` —
  `server_time` (часы панели).

- [x] **F1-5. Тексты ошибок API с подстановками.** Сервер возвращает `message` уже с подставленными значениями
  (как раньше `__()` на сервере), например «Возврат проведён: 1 500,00 KZT выданы из кассы.». Такой текст не
  является ключом и на kk/en не переведётся. Варианты: (а) сервер переводит `message` на язык клуба (каталог
  `internal/i18n`); (б) ответ несёт `message_key` + `params`. Рекомендация и решение: (а) — сервер уже знает язык
  клуба и каталог; сделать в волне 1 общим хелпером `httpx` (перевод по языку `me.club.locale`) без изменения
  контракта. До этого фронт показывает `t(message)` — для текстов без подстановок перевод работает.

- [x] **F1-6. Восстановление пароля.** Telegram Gateway — Этап 4 (DECISIONS «Telegram»). Экраны «Забыли пароль» и
  «Новый пароль» перенесены разметкой; `PasswordRecovery::available()` = false — показывается ветка «не
  подключено» старого шаблона, `/reset-password` без телефона уводит на `/forgot-password` (как `edit()`).

- [x] **F1-7. Регистрация и приглашения — отличия.**
  - Лимиты `web-register` (Q-052) и `club-invitations.accept` 10/мин; межсайтовые POST — 403 (Fetch Metadata).
  - Slug клуба: `Str::slug()` Laravel транслитерирует по таблицам voku/portable-ascii; здесь — упрощённая
    транслитерация кириллицы + 8 случайных символов (slug внутренний, уникальность даёт хвост).
  - Гонка двух регистраций одного номера — 422 «Этот номер телефона уже зарегистрирован.» (в старом — 500).
  - Принятие приглашения вошедшим: сервер переключает сессию на клуб приглашения (`current_club_id`) и
    возвращает `Me`; гость получает новую сессию (201, AuthSession), как `Auth::login()`.

- [x] **F1-8. Страницы ошибок.** Своих `resources/views/errors` в старом нет — использовались стандартные шаблоны
  Laravel (`minimal.blade.php`, 403/404/500). Перенесены разметкой (`web/src/pages/ErrorPage.tsx`). Класс
  `items-top` в шаблоне Laravel не существует в Tailwind (в старом тоже не действовал) — оставлен как есть.
  Неизвестный путь под `/_admin` для гостя даёт 404, а не вход (как Laravel: маршрута нет — 404 до `auth`).

- [x] **F1-9. Маршруты и ссылки.** Файловые маршруты TanStack Router (`@tanstack/router-plugin` 1.168.48 — парный к
  уже закреплённому `@tanstack/react-router` 1.170.46), `routeTree.gen.ts` не хранится в git (генерируется плагином
  и `npm run gen:routes`) — параллельные агенты не конфликтуют. Разметка из Blade с обычными `<a href>`: корневой
  маршрут перехватывает клики по ссылкам своего сайта (переход без перезагрузки, access-токен не теряется).
  `redirect()->intended()` — адрес в `sessionStorage` (адрес `/login` без параметров, как в старом).

- [x] **F1-10. Шрифты и иконки (Q-064).** `@fontsource/inter` 5.3.0 (400/500/600/700, все подмножества, как Google
  Fonts) и `@fortawesome/fontawesome-free` 6.4.0 (`all.min.css`, как cdnjs) — в сборке; CDN убраны из
  `index.html` и CSP (`style-src`/`font-src` — только `'self'`). Inline-скрипт темы не менялся — хеш прежний.

- [ ] **F1-11. Колокольчик уведомлений.** `NotificationsMenu` ждёт источник (`GET /notifications`, `POST
  /notifications/seen` — `ClubNotifications::for()`: журнал, заказы, чат, остатки, ПК офлайн, версия агента,
  подписка, приглашения). Эндпоинта ещё нет; `AdminShell` передаёт `notifications: null` (колокольчик без списка).
  Рекомендация: раздел `notifications` (api/notifications.yaml) в волне 1 у группы 4 (журнал действий);
  обновление — событие `notifications.changed` (`useInvalidateOn(['notifications.*'], ['notifications'])`).

- [ ] **F1-12. Изменения вне списка файлов F1.** Для подключения пришлось минимально тронуть:
  `server/internal/app/app.go` (3 строки: `ro.PlatformPool`, `ro.Valkey`, `ro.Passwords` — регистрация,
  приглашения, тикеты WS), `sqlc.yaml` (платформенные запросы в списке исключений правила `tenant-filter`),
  `db/queries/auth_register.sql`, `db/queries/layout.sql` (кроме `i18n.sql`), `.github/workflows/go.yml`
  (проверка сгенерированного REST-кода) и `web.yml` (проверка `src/api/gen`).

# Этап 4, H3 — мобильные приложения: решения и допущения

Решения приняты по принципам `docs/DECISIONS.md` (владелец поручил решать самим). Описание слоя —
[`docs/mobile-compat.md`](../mobile-compat.md).

- [x] **M-1. Как приложение с одним базовым URL работает при поклубном переходе (Q-058)?**
  - Варианты: (а) discovery-эндпоинт / ответ 307 или 409 с адресом сервера клуба — требует изменения приложений
    (базовый URL задаётся при сборке, `lib/config.dart`; Dart `http` не повторяет POST по 307); (б) маршрутизация
    в nginx — nginx не знает клуба токена `<id>|…` и телефона входа; (в) новый сервер принимает мобильные пути
    `zafiro.kz/api/(auth|guest|staff)/*` и сам решает: клуб здесь — ответ, иначе — обратный прокси на Laravel.
  - Решение: (в). Приложения и старый код не меняются; признак «клуб здесь» — токен найден в `mobile_api_tokens`
    (даже отозванный) или у телефона входа есть членство в клубе этого сервера. Настройка `mobile.upstream`;
    пусто — прокси нет (все клубы переехали).
  - Ограничение: аккаунт с клубами на обоих серверах видит только клубы того сервера, куда попал вход; такие клубы
    переносить вместе (по Q-058 клубы с мобилками — последними).

- [x] **M-2. Токены: формат и хранение.**
  - Решение: формат Sanctum 4 (`<id>|` + 40 символов + crc32b), sha256 в `mobile_api_tokens` (0024), срок 30 дней,
    один клуб. Выход/смена клуба/сброс пароля ставят `revoked_at` вместо удаления (иначе отозванный токен ушёл бы
    на старый сервер). Перенесённые токены сохраняют `personal_access_tokens.id`, новые — с 10^12.
  - `last_used_at` — не чаще раза в минуту (CLAUDE.md: не писать в Postgres на каждый запрос).
  - Сброс пароля (Telegram) отзывает токены приложений: `app.passwordResetSignOut` → `legacy.RevokeUserTokens`.
  - Сброс пароля клиента сотрудником в панели (`UserController::resetPassword`, `$user->tokens()->delete()`,
    `POST /api/customers/{id}/password`) тоже отзывает токены приложений аккаунта во всех клубах
    (`legacy.RevokeUserTokens` после коммита; тест `TestCustomersScreen`) — сделано в хвостах Этапа 4.

- [x] **M-3. Контракт без OpenAPI.**
  - Слой — обычные chi-обработчики, а не oapi-codegen strict server: контракт — внешний и замороженный (старые
    контроллеры Laravel), JSON 1:1 (порядок ключей, `null`, PHP-float `1500.0`, строки `"1500.00"`), ошибки
    `{message, errors}` без поля `error` нового REST. Спецификации у старого API не было; описание —
    docs/mobile-compat.md.

- [x] **M-4. Идемпотентность денежных операций приложения сотрудника.**
  - Приложение не шлёт `Idempotency-Key`. Решение: заголовок, если есть, иначе новый ключ на запрос — поведение
    старого API (повтор = новая операция); все движения денег — через сервисы с ledger.

- [x] **M-5. Пагинация `page`/`last_page`.**
  - Приложение сотрудника листает номерами страниц (`meta.current_page/last_page`); сохранено (OFFSET + `count(*) OVER()`),
    keyset потребовал бы изменения приложения. Размеры страниц — как в старом (25/50/30).

- [x] **M-6. Мелкие отличия от старого.**
  - `GET /api/staff/chat/poll?after=`: возвращаются последние 100 после `after` (общий запрос `ListChatThread`), в старом
    — первые 100; различие только при > 100 новых сообщениях за опрос (раз в 5 с).
  - `image_url` товаров — `null`: в схеме нового проекта картинок товаров нет (`ProductResource::imageUrl`).
  - `club_key` во входе приложения — 401 «Ключ установки недействителен.» (ключи установки заменены кодами
    регистрации ПК, Q-037); приложения поле не шлют.
  - Перевод другу кодом из Telegram: после коммита `BalanceChanged` получают ПК отправителя и друга, где они вошли
    (`billingsvc.NotifyBalancesAfterCommit`, как gRPC-путь; тест `TestTransferConfirmNotifiesBothPCs`) — сделано в
    хвостах Этапа 4.
  - Счётчик `notifications_unread` в `/api/staff/me` и `/api/staff/notifications*` — вызов раздела `notifications`
    нового REST изнутри (список собирает раздел; формат совпадает со старым).
  - Сообщение 422 с несколькими ошибками — «… (and N more errors)» по-английски, как `ValidationException::summarize()`
    без перевода; приложения показывают первую ошибку поля, а не `message`.

- [x] **M-7. Общий путь `/api/auth/login` с панелью.**
  - Мобильный вход отличается полем `device_name` (форма панели его запрещает, `additionalProperties: false`),
    `/api/auth/me` и `/logout` — токеном формата Sanctum. Остальные мобильные пути уникальны.

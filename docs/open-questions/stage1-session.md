# Этап 1 — расчёт сессии (`server/internal/billing/session`): вопросы

Пакет — чистые расчёты без БД: `Settle` (SessionSettlement), `Extend`/`EnsureComputerFor` (продление покупкой),
`IsDue`/`ExpiryFor` (истечение), `StartPackage` (запуск пакета), `AllowedZones`/`PlanTransfer`/`ListedAsFree`
(пересадка). Подключение к ledger/БД — следующий шаг.

- [x] **S1-SES-01. Прогнать фикстуру `SessionSettlement::settle()` на PHP-оракуле.**
  - Контекст: в `tools/php-oracle/eval.php` нет функции для `settle()` (ей нужна БД), поэтому вместо дифф-теста
    подготовлена фикстура `server/internal/billing/session/testdata/settle_oracle.json`: 44 сценария
    (24 — GS-046…048, GAP-001…004, GAP-036, примеры BR-032 и граничные; 20 — детерминированные случайные:
    чужие части, истёкшие лимиты, микросекунды `now`). Порядок прогона записан в поле `about` фикстуры:
    `Carbon::setTestNow(now)`, вставить части в `session_purchases` (общий `session_id`), вызвать
    `settle(..., ends_at, customer_id)`, записать в `php` ответ, созданные `time_packages` и уменьшение `total_spent`.
  - Go-тест `TestSettleOracleFixture` уже сверяет Go с полем `php`, как только оно заполнено (сейчас `null`).
  - Рекомендация: агенту оракула добавить в `GapScenariosTest.php` (или отдельный Pest-файл) цикл по фикстуре и
    записать поле `php` обратно в JSON.
  - Решение (30.10.2026): сделано: поле `php` фикстуры заполнено оракулом (44 сценария).

- [x] **S1-SES-02. Зоны пересадки из таблицы покупок: в схеме не хватает данных.**
  - Контекст: `SeatTransfers::allowedZoneIds()` (стр. 135–152) берёт последнюю запись журнала
    `tariff.purchased | time.purchased` сессии. По допущению Q-007/OQ-BR-04 источник в Go — `session_purchases`,
    но там нет (а) зоны поминутной покупки (есть только `name` = имя зоны) и (б) признака «это запуск пакета»:
    запуск пакета пишет часть `kind = tariff` с 0 тиынов, а в журнале — `time.package_started`, который старый код
    **не** учитывает. Отличить её от тарифа со 100 % скидкой (тоже 0 тиынов) по данным нельзя.
  - Варианты: (а) колонки `session_purchases.zone_id` и `source` (`purchase` | `package`), при переносе данных
    заполнить из `activity_logs`; (б) оставить источником журнал.
  - Рекомендация: (а). Pure-функция `AllowedZones` уже принимает `Source` и `ZoneID`; пакеты исключает, как старый код.
  - Решение (30.10.2026): сделано: (а) колонки `zone_id` и `source` (SV-3).

- [x] **S1-SES-03. Пересадка: удалённый тариф снимает ограничение зон, а запуск пакета — нет.**
  - Контекст: `allowedZoneIds()` ищет тариф через `Tariff::find()` **без** `withTrashed` → мягко удалённый тариф
    = «любая зона». `startPackage()` (стр. 183) берёт `$package->tariff` с `withTrashed` → зоны удалённого тарифа
    действуют. В Go повторено как есть (`ZonePurchase.TariffFound` = найден и не удалён).
  - Рекомендация: оставить (перенос), но отметить в BR-035 — сейчас там этого нет.
  - Решение (30.10.2026): принята рекомендация: оставить, дописать в BR-035.

- [x] **S1-SES-04. Список свободных ПК и проверка пересадки различаются.**
  - Контекст: `freeSeatsFor()` (стр. 31–42) считает ПК занятым по `session_ends_at > now()` и онлайн по SQL
    `last_seen_at >= now() − 90 с`, где `now()` подставлен строкой без долей секунды; `transfer()` (стр. 95–99)
    использует `hasPaidSession()` и `connectionStatus()` с микросекундами. Итог: ПК с `session_ends_at` в будущем,
    но без пользователя/гостя, в списке «занят», а пересадка на него разрешена; ПК с heartbeat ровно 90.x с назад
    в списке «доступен», а пересадка отказывает. В Go — две функции `ListedAsFree` и `FreeForTransfer`, буквально.
  - Рекомендация: оставить как есть до визуального сравнения; расхождение — доли секунды и невозможное в норме
    состояние ПК.
  - Решение (30.10.2026): принята рекомендация: оставить как есть.

- [x] **S1-SES-05. Ledger минут: что записывать о потерянном времени.**
  - Контекст: при расчёте теряются (а) остаток тарифа без лимита, (б) остаток тарифа с истёкшим лимитом,
    (в) неполная минута пакета (`intdiv($seconds, 60)`), (г) время чужой части. Старый код это нигде не фиксирует.
    `Settle` отдаёт по каждой части `UnusedSeconds`, `LostSeconds`, `Outcome`.
  - Варианты: писать в ledger минут только созданные пакеты (как Q-011) или ещё и «сгорело N секунд».
  - Рекомендация: только аудит (детали в `audit_log`), без проводок ledger: деньги за них не двигаются.
  - Решение (30.10.2026): принята рекомендация: только аудит, без проводок ledger.

- [x] **S1-SES-06. Естественное истечение (Q-010) — подтверждение допущения.**
  - Контекст: `expireIfDue()`/`expireAll()` не вызывают `settle()`; части не удаляются, журнала нет (GAP-005).
    `ExpiryFor` повторяет это (`Settle=false`, `DeletePurchases=false`, `Log=false`), допущение Этапа 1 — Q-010.
    Расчёт при этом ничего бы не изменил: `left = 0` → возврата и пакетов нет, поэтому удаление частей (вариант (б)
    Q-010) безопасно для денег.
  - Также: `end()` (стр. 203–229) проверяет только `current_session_id`, а не `hasPaidSession()`, поэтому
    «досрочно» завершить уже истёкшую, но ещё не снятую сессию можно: `settle()` с `left = 0` удалит части без возврата.
  - Решение (30.10.2026): по DECISIONS Q-010 — части не удаляются, плюс событие `computer.session_expired` в журнал.

- [x] **S1-SES-07. Усечение секунд в пользу клиента.**
  - Контекст: `settle()` стр. 31 и `startPackage()` стр. 176 считают `getTimestamp()` разность — доли секунды `now`
    отбрасываются, поэтому клиент получает до 1 с «лишнего» времени (возврат за 1800 с при фактических 1799.1).
    Новые даты, которые старый код сохранял в MySQL (`session_ends_at`, `expires_at`), усекались до секунды
    форматом `Y-m-d H:i:s`. Postgres хранит микросекунды — в Go всё сохраняемое проходит через `StoredTime`
    (усечение). Исполнителю (sqlc-слой) важно не писать `now()` Postgres напрямую в эти колонки.
  - Рекомендация: повторить буквально (сделано); подтвердить, что сервер всегда передаёт время из Go, а не `now()` SQL.
  - Решение (30.10.2026): принята рекомендация: повторить буквально; сохраняемое время передаёт Go (`StoredTime`), не `now()` SQL.

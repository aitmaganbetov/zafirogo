# Этап 3, G1 — дашборд, карта клуба, список ПК: вопросы и принятые решения

Владелец поручил решать самостоятельно по принципам `docs/DECISIONS.md`; ниже — решение и обоснование.

- [x] **CM-1. F1-5: тексты ошибок API на языке клуба.** Сделано общим хелпером `httpx` (`server/internal/http/httpx/i18n.go`):
  `ResponseError` переводит `message` и `errors` по каталогу (`httpx.Deps.I18n` — `i18n.Catalog`, язык клуба
  `clubs.locale` с кэшем 30 с). Тексты с подстановками — `httpx.ValidationMsg / ErrorMsg / FormErrors.AddMsg`
  (ключ + параметры); доменные ошибки cash/billing/pricing уже идут так через `MapError`. Тексты правил валидатора
  (`RuleError`, `RuleMessage`) переводятся как валидатор Laravel: `validation.<правило>` + `validation.attributes.<поле>`
  (в старом русском интерфейсе было «Поле «сумма» обязательно.», в новом до этого — английский шаблон). Текст успешного
  ответа — `d.T(ctx, ключ, params)` (с `count` и «|» — как `trans_choice`). Перевода нет — русский текст (как `__()`).
  Конвенция — `api/README.md`. Тест — `httpx/i18n_test.go`, `TestErrorMessagesInClubLocale`.

- [x] **CM-2. Статус ПК — из присутствия.** `ClubComputer::currentStatus()` перенесён (`server/internal/clubmap/state.go`),
  но «в сети» — по присутствию агента в Valkey, а не по свежести `last_seen_at` (heartbeat в Postgres больше не пишется).
  Подсветка (`pc-staff/pc-guest/pc-account/pc-free`) и «что куплено» считает сервер (`light`, `session_tariff`).

- [x] **CM-3. Опрос `/club-map/state` → WebSocket.** Событие `computer.state` пишут: присутствие (подключение, смена
  состояния/сессии, закрытие стрима — `clubmap.PresenceEvents`, подключён в `app.go` как `stream.Options.Presence`;
  офлайн после ожидания — `Sweeper.OnOffline`), сервисы сессий (как было), правки карты и управление ПК. Клиент
  применяет связь сразу, остальное досылает одним `GET /api/club-map/state?ids=…` на пачку событий (300 мс); событие
  без `computer_id` (удалена зона) — перечитать экран. Дашборд и список ПК перечитываются по `computer.*`.

- [x] **CM-4. Включение ПК (Wake-on-LAN).** В старом магический пакет слали все включённые ПК в своём heartbeat.
  Теперь — команда `WakeOnLan` (MAC выбранных, ≤ 50) не более чем 5 включённым ПК клуба с возможностью `wake_on_lan`
  (`clubmap.MaxWakeRelays`): N команд на клуб при 50 000 ПК не нужны, нескольких ПК одной сети достаточно. Тексты
  ответа — как `controlMessage()`.

- [x] **CM-5. «Агент устарел» по возможностям.** `ComputerPower::carriesOut()` сравнивал версию агента. Теперь ПК в сети
  проверяется по `Hello.capabilities` (`power_control`, `service_mode`, `show_message`), ПК не в сети — устаревшим
  считается только ПК, агент которого ни разу не сообщил версию (как `carriesOut(null)`); команда ждёт его в очереди
  (2–5 мин). Версия в тексте «обновите до версии …» — объявленный релиз (`platform_settings.agent_release`), без
  него — минимальные версии старого агента (0.0.66 / 0.0.72 / 0.0.73).

- [x] **CM-6. Q-018 — удаление зоны.** `clubmap.DeleteZone`: при идущей сессии (`hasPaidSession()`) на ПК зоны — 422
  «На ПК зоны идёт сессия: удалить зону можно после её окончания.» (новый текст); тарифы зоны, у которых не останется
  других зон, выключаются (`is_active = false`) в той же транзакции, имена — в ответе и в сообщении («Тарифы без зон
  выключены: …»), id — в журнале `zone.deleted` (`tariffs_disabled`). Тест — `TestClubMapDeleteZoneQ018`.

- [x] **CM-7. Отличия от старого на карте (осознанные).**
  - Двойной обработчик перетаскивания зон в шаблоне (~стр. 158 и 159 — один и тот же код дважды) давал два PATCH на
    одно перемещение; перенесён один (поведение второго: минимум дивана 80×60).
  - Диалог «Уведомление на ПК» в шаблоне вложен в `@if(cash.create)`: без права кассы кнопка «Уведомление» ничего не
    делала. Теперь диалог — по праву `pc_control.update` (как кнопка).
  - После правок зоны/ПК страница не перезагружается: данные перечитываются, режим редактора сохраняется, ошибка формы
    — в `cm-alert error` сверху (как после редиректа), диалог зоны остаётся открытым с введёнными значениями (в старом
    открывался пустым). Ошибки карточки ПК — все ошибки формы в `cm-form-errors`, но сервер отдаёт первую ошибку
    (правила проверяются по порядку).
  - Режим просмотра суперадмина: кнопки изменения скрыты.
  - Дата в «Информации о ПК» — `Intl` в поясе клуба (в старом — пояс браузера).
  - Сумма `hidden is_featured=0` формы зоны сохранена (как в старом, флаг при правке сбрасывается).

- [x] **CM-8. Дашборд.** «ПК забронировано» — только ручной флаг (`is_reserved`): `DashboardController` не отмечал
  `bookedNow` (это делает только карта). Перенесено как есть. Кассиру и оператору API отвечает 403 (старый код уводил
  их на кассу и список ПК — фронт делает тот же переход). Подписка (`subscription`) нигде в REST пока не проверяется —
  общий вопрос каркаса.

- [x] **CM-9. Подключение ПК (новый экран `/club-computers/enrollment`).** Коды регистрации, ключи образа, ожидающие
  ПК — REST `api/computers.yaml` поверх `agent/enroll`; права — роли сервиса (коды и ожидающие ПК: owner, admin,
  manager, operator; ключи образа: owner, admin). Разметка — по образцу карточки «Ключ установки клуба»
  (`<x-settings.card>`, поле с «Копировать») и таблиц списка ПК. Ссылка — в подзаголовке «Список ПК» (не меняет вёрстку).
  Перерегистрация / отключение ПК (`Reregister`, `RevokeComputer`) в интерфейс не выведены — нет места в старых экранах;
  при необходимости — кнопки в диалоге ПК на карте.

- [x] **CM-10. Визуальный стенд.** Для одинаковых снимков: `visual-seed` пишет присутствие агентов в Valkey для ПК,
  которые старый код показывает «в сети» (`last_seen_at` не старше 90 с от «сейчас»); `new.sh` импортирует переводы
  (формы `trans_choice` берутся только из каталога — без них «7 операций сегодня|…» показывалось целиком); воркер
  истечения сессий берёт часы `dev.fixed_now` (иначе снимал демо-сессии по реальному времени).

- [ ] **CM-11. Риск: формы множественного числа без каталога.** Если ключа `trans_choice` нет в пакете переводов (новый
  текст, не попавший в `translations`), i18next показывает строку со всеми формами. Рекомендация каркасу (`web/src/i18n`):
  обработчик отсутствующего ключа, выбирающий форму из ключа по правилу языка.

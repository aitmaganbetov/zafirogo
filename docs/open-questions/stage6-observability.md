# Этап 6, O3 «Наблюдаемость»: решения и вопросы

Решения приняты по принципам `docs/DECISIONS.md` (владелец поручил). Описание стека — `docs/observability.md`.

## OBS-1. Библиотека метрик

- [x] **Вопрос.** prometheus/client_golang или OpenTelemetry metrics с Prometheus-экспортёром?
- **Решение.** `github.com/prometheus/client_golang` v1.25.0 (08.10.2026, ≥ 14 дней, PD-4). Трассировка — OpenTelemetry
  SDK v1.47.0 с `otlptracehttp` (02.10.2026). Обоснование: стандартный формат `/metrics` без промежуточного слоя,
  свой реестр на App (несколько App в одном тестовом процессе), стандартные сборщики Go runtime/процесса;
  OTel metrics добавил бы ещё один SDK и экспортёр ради того же результата. Транзитивно поднялись
  `genproto/googleapis/rpc` (28.09.2026), `testify` 1.12.1, `klauspost/compress` 1.20.1 — все старше 14 дней; `grpc` остаётся 1.84.0.

## OBS-2. Порт метрик по умолчанию выключен

- [x] **Решение.** `observability.metrics_listen` по умолчанию пусто (выключено), а не `127.0.0.1:9090`: внутри
  контейнера 127.0.0.1 недоступен Prometheus, а 9090 конфликтует с самим Prometheus при локальном запуске; явное
  включение в окружении (staging — `:9090` во внутренней сети compose) безопаснее (принцип 4). Порт — отдельный
  `http.Server` только с `GET /metrics`, без pprof.

## OBS-3. Loki не добавлен в репозиторий

- [ ] **Вопрос.** Нужен ли централизованный сбор журналов (Loki) уже на staging?
- **Контекст.** Журналы — JSON в stdout; `request_id`/`trace_id` есть в каждой записи запроса. Описание варианта — `docs/observability.md` §7.
- **Рекомендация.** Подключить вместе с прод-окружением (Grafana Loki + Alloy, хранение 14–30 дней, метки без `request_id`/`club_id`).

## OBS-4. Экспортёры инфраструктуры

- [ ] **Вопрос.** postgres_exporter, prometheus-nats-exporter, blackbox (срок HTTPS-сертификата балансировщика) — в staging-оверлей?
- **Контекст.** Сервер отдаёт свои пулы, ошибки Valkey/NATS и сроки сертификатов gRPC; состояние самих Postgres/NATS
  и HTTPS балансировщика (TLS терминирует прокси, Q-071) сервер не видит.
- **Рекомендация.** Добавить с прод-окружением; HTTPS-сертификат балансировщика — blackbox_exporter (`probe_ssl_earliest_cert_expiry`)
  с тем же порогом 21 день.

## OBS-5. Срок сертификатов и PD-5

- [x] **Решение.** PD-5 запрещает новую функцию продукта (алерт о сроке TLS в суперадминке, `monitoring:certificates`
  переносится как есть). Метрика `zafiro_tls_certificate_expiry_timestamp_seconds` и алерты Prometheus — эксплуатация,
  не функция продукта; поручены оркестратором в задаче O3. Интерфейс не меняется.

## OBS-6. События предметной области через трассировщик pgx

- [x] **Решение.** Счётчики ledger, команд агентам, вебхуков, outbox и запусков задач получены трассировщиком pgx по
  именам запросов sqlc (`-- name: …`) и тегам результатов — без правок пакетов `ledger`, `agent`, `webhook`, `outbox`,
  `worker` (вне зоны O3). Позиции аргументов проверяет `pgx_test.go` на сгенерированном `store`.
- [ ] **Вопрос на будущее.** Перенести счётчики в сами пакеты (явные хуки), когда они будут меняться по другим причинам?
  **Рекомендация:** да для ledger и команд агентам — прямой вызов надёжнее разбора SQL; трассировщик оставить для метрик запросов и спанов.
- Ограничение: `worker_errors_total` для задач считается по записям журнала warn/error с атрибутом `job` (так пишут все
  задачи `worker/*`, `monitoring/workers.go`); задача, которая начнёт логировать иначе, выпадет из счётчика.

## OBS-7. Пул pgx создаётся в app, а не db.NewPool

- [ ] **Вопрос.** `db.NewPool` не принимает трассировщик; `app.newPool` повторяет его (разбор DSN, пул, пинг 5 с) и добавляет
  `ConnConfig.Tracer` и `BeforeClose`. Добавить в `db` параметр (опции пула), чтобы не было двух копий?
- **Рекомендация.** Да, `db.NewPool(ctx, dsn, ...func(*pgxpool.Config))` — малой правкой владельца пакета `db`.

## OBS-8. Запросы при сборе метрик — без sqlc

- [x] **Решение.** Агрегаты очереди вебхуков и outbox, `pg_locks` для лидера — константы SQL в `observability/collectors.go`
  (платформенный пул, только агрегаты без `club_id`, по существующим индексам). Запрос outbox совпадает с
  `store.CountUnpublishedOutboxEvents`. Перенести в `db/queries/monitoring.sql` при следующей генерации sqlc.

## OBS-9. Заметка для O5: closers в app.Build

- [ ] Замыкания `func() { _ = a.httpLis.Close() }` и `a.grpcLis` в `Build` обращаются к именованному результату `a`,
  который при `return nil, err` уже nil: если ошибка случится после их регистрации (например, `grpc listen` или
  `ProxyTrustedPrefixes`), `closeResources` разыменует nil. Свои замыкания O3 захватывает локальными переменными
  (`obs`, `mlis`). Рекомендация — так же для остальных.

## 1. Нет rate limit на веб-входе и регистрации
- Контекст: `POST /login` и `POST /register` в `routes/web.php:158, 165` без `throttle:`; `AuthController@login` сам попытки
  не считает. В API те же действия под `throttle:customer-login` (`routes/api.php:38, 43`).
  Правило ТЗ — «rate limiting на тех же маршрутах, где он был» — формально лимита нет.
- Варианты: (а) перенести как есть, без лимита; (б) добавить лимит как у `customer-login` (5/мин на IP+телефон, 300/мин на IP).
- Рекомендация: (б) — это изменение поведения, нужно ваше согласие.
- Решение (30.10.2026): см. [Q-052](../OPEN_QUESTIONS.md#q-052) — по DECISIONS Q-052 — лимит на веб-вход и регистрацию включён по умолчанию.

## 2. Опросы → WebSocket: какие события и в каком объёме
- Контекст: 5 мест опроса (`docs/parts/10-screens.md`, раздел «Polling → WebSocket»): уведомления 60 с, карта клуба 15 с,
  чат 5 с, To Do 15 с, заказы 15 с. Три экрана делают `location.reload()` при изменении.
- Варианты: (а) WS шлёт только «что-то изменилось» (invalidate), клиент перезапрашивает REST (TanStack Query);
  (б) WS шлёт готовые данные (диффы состояния ПК, сообщения чата).
- Рекомендация: карта клуба и чат — (б) (частые события, 5 000–50 000 ПК); To Do, заказы, уведомления, бейджи — (а).
  Полную перезагрузку страницы не переносить. Нужно согласовать с частью «API и агент».
- Решение (30.10.2026): см. [Q-062](../OPEN_QUESTIONS.md#q-062) — по DECISIONS Q-062 — WebSocket шлёт готовые изменения данных (не «что-то изменилось»); `location.reload()` не переносим.

- Решение (30.10.2026): см. [Q-063](../OPEN_QUESTIONS.md#q-063) — по DECISIONS Q-063 — да, «живые» бейджи по WebSocket (замена опроса).

## 5. Формат плейсхолдеров в ключах переводов
- Контекст: ключи — русский текст с плейсхолдерами Laravel `:name` (`CLAUDE.md` Zafiro, «Локализация»; `database/translations/*.php`,
  таблица `translations`). i18next по умолчанию использует `{{name}}`; ещё он делит ключи по `.` и `:` (keySeparator/nsSeparator).
- Варианты: (а) хранить ключи как в Laravel (`:club`) и написать своё форматирование для i18next (post-processor);
  (б) при переносе переводов конвертировать `:name` → `{{name}}` в ключах и значениях.
- Рекомендация: (б) + обязательно `keySeparator: false, nsSeparator: false`. В `AdminLayout.tsx` уже использован ключ
  `'Вы смотрите клуб «{{club}}» как суперадмин. Только просмотр: изменения недоступны.'`. Нужно решение до выгрузки переводов (часть «модели и БД»).
  Отдельно: `trans_choice` с тремя формами (ru), одной (kk), двумя (en) → i18next plurals (`_one/_few/_many`) — конвертер тоже нужен.
- Решение (30.10.2026): см. [Q-065](../OPEN_QUESTIONS.md#q-065) — по DECISIONS Q-065 — ключи прежние; плейсхолдеры конвертируются в формат i18next при импорте; редактор суперадминки показывает формат Laravel.

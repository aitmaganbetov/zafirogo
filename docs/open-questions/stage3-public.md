# Этап 3, группа 7 — QR-вход на ПК, публичные страницы, PWA, сквозные доделки: решения

Владелец поручил решать по принципам `docs/DECISIONS.md`; ниже — что решено и почему.

- [x] **G7-1. Справка Integration API (`/docs/api`) до Этапа 4.** Integration API v1 переносится на Этапе 4, а страница —
  публичная документация без данных клуба. Решение: страница переносится сейчас — Swagger UI **5.17.14 из npm**
  (Q-064, отдельная страница сборки `web/docs/api/index.html`, без стилей SPA, как `api-docs.blade.php`), спецификация —
  **копия** `resources/api/openapi-v1.yaml` старого проекта, вшитая в бинарник
  (`server/internal/http/sections/public/openapi-v1.yaml`, `GET /docs/api/openapi.yaml`, `application/yaml`). Принцип 2
  (тот же экран и контракт); клубы переходят на новый сервер только после Этапа 4, поэтому описанный API к тому времени
  будет реализован. Этап 4: заменить копию файлом нового `api/integration-v1.yaml`, если контракт уточнится.
  Отличие: в старом — CDN jsdelivr с SRI, в новом — из сборки (CSP без внешних источников). Визуальное сравнение —
  `pending` (в стенде CDN старого заблокирован, старая страница пустая).

- [x] **G7-2. Wiki (Q-069).** `resources/wiki/index.html` перенесена в `web/wiki/index.html` (вторая HTML-страница сборки
  Vite) без изменений, кроме шрифтов: Google Fonts → `@fontsource/golos-text|unbounded|jetbrains-mono` 5.3.0 (Q-064).
  Сервер (`server/internal/webui/wiki.go`): без `ZAFIRO_HTTP_WIKI_HOST` — `/wiki`; с ним — корень хоста wiki, прочие адреса
  хоста — 302 на корень (`RestrictWikiHost`), `/wiki` сайта — 301 на хост wiki. `Cache-Control: public, max-age=300`,
  CSP с sha256 inline-скрипта страницы. Ссылки «Wiki» лендинга ведут на `/wiki` (с хостом wiki — тот же 301, что у
  старого адреса), поэтому лендингу не нужен адрес хоста.

- [x] **G7-3. Офлайн-страница — HTML сервера, не маршрут SPA.** `GET /offline` рендерит Go (`sections/public`) — разметка и
  стили `offline.blade.php` дословно, тексты всех включённых языков встроены (как `PwaController::offline`). SPA-маршрут
  не годится: без сети он не загрузит переводы и данные. Отличие: `onclick="location.reload()"` перенесён в скрипт в
  конце страницы (CSP без `'unsafe-inline'`; оба скрипта — по sha256 в заголовке CSP ответа).

- [x] **G7-4. Service worker (Q-068).** `web/public/sw.js` переписан под сборку Vite: ассеты `/assets/*` (JS, CSS, шрифты из
  npm) — cache-first (до 200 файлов вместо 60: сборка делится на чанки), `/icons|images` — stale-while-revalidate,
  навигация — сеть, без сети — закэшированная `/offline`; `/api`, `/ws`, POST — мимо. Как в старом, **страницы (в т. ч.
  `index.html`) не кэшируются**: оболочка SPA без сети всё равно не загрузит данные клуба, а устаревший `index.html`
  ссылался бы на ассеты прошлой сборки. «Кэш оболочки» = офлайн-страница с иконкой (при установке) + ассеты сборки.
  При активации удаляются все прежние кэши `zafiro-*` (включая кэши старого Laravel на том же домене). Регистрация — только
  в prod-сборке (`src/pwa/register.ts`), в защищённом контексте, после `load`, как `resources/js/app.js`.
  Манифест — `GET /manifest.webmanifest` (Go, язык гостя, ярлыки Касса/Склад/Список ПК), `<link rel="manifest">` в
  `index.html`. PWA-баннер уже был в `AdminLayout` — теперь у него есть манифест и SW (событие `beforeinstallprompt`).

- [x] **G7-5. Проверка подписки (`RequireActiveSubscription`).** Middleware роутера (`server/internal/http/subscription.go`)
  для `/api/*`: выбранный клуб без активной подписки (`ClubSubscription::isActive()`; нет подписки — неактивна) →
  `402 {"error":"subscription_inactive","message":"Подписка клуба не активна."}`. Исключения — как маршруты без
  `subscription` в `routes/web.php:169–176` и вне группы клуба: `/api/auth/*` (вход, выход, смена клуба), `/api/billing*`,
  `/api/notifications*`, `/api/layout/*` (каркас есть и на странице подписки), `/api/i18n*`, `/api/ws-ticket`,
  `/api/invitations/*`, `/api/superadmin/*`, `/api/pc-login/*`, `/api/landing`. Фронт: ошибка маршрута 402 → переход на
  `/billing` (`RouteErrorPage`), как `redirect()->route('billing.show')`. Строка подписки кэшируется в процессе на 10 с
  (срок сверяется с часами на каждом запросе), продление видно не позже чем через 10 с.
  Включается `httpserver.Options.RequireSubscription` (в `app` — всегда); тестовые окружения других разделов создают
  клубы без подписки и его не включают. Экран `/billing` перенесён (G7-10).

- [x] **G7-6. QR-вход: клуб — клуб кода.** Страница знает только код; открытый вход ищется пулом `zafiro_platform`
  (`PcLoginFindOpen`, как `withoutGlobalScope('club')`), подтверждение — `guestapi.Server.ApproveQrLogin` того же
  экземпляра, что обслуживает `WatchQrLogin` ПК (`app.go`). Вход ради QR разрешён клиентам: страница входа шлёт
  `pc_login: true`, если сохранённый адрес возврата начинается с `/pc-login/` (как `url.intended`). Вход «уже не открыт»
  при подтверждении — `approved: false` и экран «QR-код устарел» (в старом — редирект на ту же страницу). Ошибки
  (`Аккаунт заблокирован…`, `Ваш аккаунт не состоит в этом клубе.`, «вошёл на другом ПК», `Подписка клуба не активна.`) —
  422 под `code`, показ — блок `.auth-errors`, как `$errors->first()`. Лимит `throttle:10,1,pc-login.approve`.
  Текст «вошёл на другом ПК» приходит с подставленными параметрами на русском и не переводится (как и в gRPC агента).

- [x] **G7-7. Перерегистрация и отключение ПК.** Новые операции раздела computers:
  `POST /api/agent-enrollment/computers/{id}/reregister` (201, код один раз) и `/revoke` (200), роли — как у кодов
  (`enroll.CanRegister`, в режиме просмотра суперадмина — нет). На экране «Подключение ПК» — карточка
  «Перерегистрация и отключение ПК»: выбор ПК (список всех ПК клуба в ответе `GET /api/agent-enrollment`, поле
  `computers`, только при `can_register`) и две кнопки с `confirm`, в стиле кнопок экрана. Карточку ПК на карте клуба
  (визуально сверенный экран G1) не меняли. Новые ключи перевода: «Перерегистрация и отключение ПК», «ПК», «Выберите ПК»,
  «Перерегистрировать», «Отключить», «ПК отключён.», тексты подсказки и подтверждений.

- [x] **G7-8. CM-11 (формы без каталога).** `web/src/i18n/missing.ts` — `parseMissingKeyHandler` i18next: ключ trans_choice
  с `count` → одна форма по `MessageSelector::choose()` (явные `{n}`/`[a,b]`, иначе правило ru — ключ русский), обычный
  ключ → ключ с подстановками. Совпадает с `server/internal/i18n` `Choose()`.

- [x] **G7-9. Лендинг.** `GET /api/landing` (`trial_days` — `max(trial_days)` активных планов `?: 14`, `download_url` —
  `AgentUpdate::downloadUrl() ?? AGENT_DOWNLOAD`). `<title>` — без суффикса « · Zafiro», как шаблон; `og:*`/`description`
  ставятся в `<head>` скриптом (у SPA нет серверного `<head>` страницы; для превью ссылок в мессенджерах — открытый
  вопрос на будущее, если понадобится, — серверный рендер `<head>` для `/`). Ссылки «Wiki» — `data-reload` (вне SPA).

- [x] **G7-10. Экран «Подписка» (`/billing`).** Раздел `billing` (`api/billing.yaml`, `GET /api/billing`): право
  `billing.view` (`billing.show`), без проверки подписки. Разметка `billing/index.blade.php` дословно; статус — как
  шаблон (`isActive()` / `isPastPaidPeriod()`: «Истекла», «Не активна», «Пробный период», «Активна»), вычисляется на
  сервере с часами приложения. Даты — в UTC, как `->format()` старого (часовой пояс приложения, не клуба). Название плана
  — через `t()`, как `__($subscription->plan->name)` в шаблоне (осознанное исключение «данные БД не через t()»: так в
  старом). Демо-данные: клуб 2 «Zafiro Lite» с истёкшей подпиской и его владелец (роль входа `owner_expired`).

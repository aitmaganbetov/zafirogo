# Этап 6, O5 — решения ревью безопасности

Решены по принципам `docs/DECISIONS.md` (поручение владельца 30.10.2026). Находки — `docs/security-review.md`.

## SQ-1. Общий лимит попыток входа на аккаунт (SEC-004)

- **Контекст.** `server/internal/auth/ratelimit/rules.go`: `web-login`, `customer-login` — `phoneAndIP(5, 300)`:
  5/мин на пару «IP + телефон» и 300/мин на IP. Счётчика «на телефон с любых IP» нет (в старом — так же для
  `customer-login`; для веб-входа лимита не было вовсе, Q-052).
- **Варианты.** (а) Как есть. (б) Добавить счётчик на телефон (например, 30 за 15 мин). (в) Прогрессивная задержка.
- **Решение: (а).** Счётчик на телефон даёт любому, кто знает номер кассира или владельца, держать его вход
  заблокированным (отказ в обслуживании клуба в начале смены) — это хуже риска, который он снимает: пароли — Argon2id,
  неудачные попытки пишутся в журнал (PD-13), перебор с одного IP ограничен. Пересмотреть, если журнал покажет
  распределённый перебор (тогда — (в) с CAPTCHA, это новая функция).

## SQ-2. Второй фактор для суперадмина (SEC-010)

- **Контекст.** Кабинет суперадмина видит все клубы; вход — телефон и пароль, как в старом.
- **Решение: не добавлять в рамках переноса** (принцип 3: новая функция). Смягчение уже есть: отдельный домен
  (Q-069), лимит входа (Q-052), режим просмотра без записи (Q-054 + SEC-001), журнал `platform_logs`, права
  `zafiro_app` на платформенные таблицы урезаны (SEC-005). Рекомендация владельцу — TOTP для суперадминов первым
  пунктом после перехода.
- [x] **Сделано (Этап 7, поручение владельца):** TOTP обязателен для всех суперадминов — после пароля полувход и
  принудительная настройка, коды восстановления, сброс другим суперадмином и командой `zafiro superadmin-totp-reset`.
  [`stage7-totp.md`](stage7-totp.md), SEC-010 в `docs/security-review.md`.

## SQ-3. HSTS на каждом ответе (SEC-018)

- **Контекст.** `docs/open-questions/infra.md` §1: TLS терминируется на прокси, HSTS «ставит прокси». Если прокси
  настроен без HSTS, заголовка нет нигде.
- **Решение:** сервер ставит `Strict-Transport-Security: max-age=63072000; includeSubDomains` всегда (принцип 4).
  По RFC 6797 §8.1 браузер игнорирует его на ответах по HTTP — локальная разработка по `http://` не затронута.
  Если прокси тоже ставит HSTS — значения совпадают. `includeSubDomains` — на домене панели; поддомены, которым нужен
  HTTP, на нём не размещаются (кабинет и wiki — свои домены с HTTPS).

## SQ-4. Права пула клуба на платформенные таблицы (SEC-005)

- **Контекст.** `0004_rls.sql` выдавал `zafiro_app` и `zafiro_platform` `SELECT, INSERT, UPDATE, DELETE` на все
  таблицы; без RLS остались `users`, `clubs`, `platform_settings`, `saas_plans`, `platform_logs` и др.
  (`docs/schema-changes.md` §10.8).
- **Решение:** миграция `0028_least_privilege.sql` — пул клуба получает только то, чем пользуется код:
  - `users`: `INSERT`/`UPDATE` только колонок профиля и пароля (`is_superadmin`, `blocked_at` — только платформа),
    без `DELETE`;
  - `clubs`: RLS без FORCE — читают все, `UPDATE` пулом клуба — только строки `id = app.club_id`, `INSERT`/`DELETE` —
    только платформа (владелец схемы не ограничен: миграции, `zafiro_purge_imported_club`);
  - `platform_settings`, `saas_plans`: только чтение; `platform_logs`: чтение и добавление; `goose_db_version`: нет.
  RLS на `users` не включаем: пул клуба законно меняет пароль клиента клуба и свой профиль гостя (условие — в
  запросах), а политика «член текущего клуба» потребовала бы `app.user_id` во всех путях входа — риск поломки выше
  пользы при уже урезанных колонках. Переводы (`languages`, `translations`) остаются доступными на запись: каталог
  переводов пула клуба дописывает недостающие ключи (`I18nInsertMissing`).

## SQ-5. Что разрешено в режиме просмотра (SEC-001)

- **Контекст.** Laravel (`SetCurrentClub::viewAsSuperadmin`) пропускал в режиме просмотра только безопасные методы и
  маршруты `superadmin.*`, `auth.logout`.
- **Решение:** `readOnlyGuard` разрешает не-GET только для `/api/superadmin/*` (кабинет, выход из режима
  просмотра), `/api/auth/login|refresh|logout|logout-all` и `POST /api/ws-ticket` (билет только для чтения событий).
  Остальное — 403 `read_only`, в том числе подтверждение QR-входа на ПК (`POST /api/pc-login/{code}`) и выбор клуба:
  в старом они тоже были под `current-club` и отклонялись. `/api/v1` (API-ключи) режима просмотра не имеет.

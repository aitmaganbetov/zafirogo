# Этап 3 — итоговый отчёт: экраны React

План — [`stage-3-plan.md`](stage-3-plan.md). Решения по ходу этапа — `docs/open-questions/stage3-*.md`
(владелец поручил решать самостоятельно по принципам [`DECISIONS.md`](DECISIONS.md)).

## Что сделано

Все 50 экранов из [`parts/10-screens.md`](parts/10-screens.md) перенесены на React с дословной разметкой и
Tailwind-классами Blade, поверх сервера Этапов 1–2; добавлен новый экран «Подключение ПК» (коды регистрации,
ключи образа для бездисковых ПК, ожидающие ПК — решение Q-037).

| Группа | Экраны |
|---|---|
| Вход и регистрация | вход, регистрация, «Забыли пароль», «Новый пароль», приглашение |
| Админка клуба | дашборд, карта клуба, список ПК, подключение ПК; касса, операции смены, чек, X/Z-отчёты с печатью Z перед закрытием смены, склад, остатки, заказы с ПК, услуги; клиенты, сброс пароля, сотрудники, права (список и матрица); тарифы, бронирования, новости, задачи, чат, журнал действий, уведомления; настройки (клуб, языки, финансы, гости, интеграции); подписка |
| Суперадминка (свой домен, Q-069) | сервер и мониторинг, клубы, карточка клуба, пользователи, тарифы платформы, новости платформы, журнал, языки, редактор переводов, Telegram |
| ПК и публичные | QR-вход (показ кода, код устарел, готово), лендинг, офлайн, справка API, wiki |

Основа: API разбит на разделы (по файлу OpenAPI и сгенерированному пакету на раздел — агенты работали
параллельно без конфликтов), маршруты TanStack с теми же URI, вход с ротацией токенов и CSRF, переводы с сервера
(импортированы из старых файлов: 2248 строк на язык; ошибки API переводятся на язык клуба), шрифты и иконки из npm.

## Замена опроса на push

Все 5 мест polling (уведомления, карта клуба, чат, задачи, заказы) и бейджи меню работают по WebSocket;
состояние ПК на карте и дашборде — из присутствия агента в реальном времени.

## Проверка

- **Визуальное сравнение** (`task visual`: оба приложения на одних демо-данных с замороженным временем,
  desktop и mobile, светлая и тёмная тема): **202 снимка совпали, 0 расхождений, 0 ошибок**. 4 снимка в статусе
  «отложено» осознанно: журнал действий на мобильном (порядок ключей в описании: sqlite в стенде старого против
  порядка БД) и справка API (в стенде старая страница пустая — CDN заблокирован).
- Интеграционные тесты каждого раздела (HTTP → сервис → Postgres/Valkey/NATS), матрица прав, режим просмотра
  суперадмина, изоляция клубов; Vitest — 126 тестов; Playwright e2e по разделам.
- go vet, golangci-lint, gosec, sqlc vet, проверка, что сгенерированный код совпадает со спецификациями, — чисто.

## Найдено и исправлено по ходу

- Ошибки старого кода (поведение улучшено, записано в решениях разделов): ссылка приглашения не показывалась;
  ошибки формы редактирования клиента открывались в чужом диалоге; удалённый сотрудник оставался в системе;
  отмена заказа клиенту без строки баланса теряла деньги; страница склада падала на движениях удалённого товара;
  обработчик перетаскивания зон срабатывал дважды; «Диск: использовано» на экране сервера считалось иначе, чем в PHP.
- Удаление зоны запрещено при идущих сессиях, тарифы без зон выключаются (Q-018).
- Проверка подписки клуба в REST (402 → экран подписки), как `RequireActiveSubscription` старого.

## Осознанные отличия

- На складе выпадающий список товаров заменён полем поиска (большие клубы), поле на 2 px выше; на кассе товары
  подгружаются при прокрутке, клиент ищется на сервере (Q-070).
- Журнал действий листается «Назад/Вперёд» (партиционированная таблица, keyset).
- Пагинация клиентов — keyset (Предыдущая/Следующая).

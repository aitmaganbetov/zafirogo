# Этап 4 — интеграции

Цель: перенести всё, что связывает Zafiro с внешним миром, чтобы клуб можно было перевести на новый сервер без
потери функций. Решения — [`DECISIONS.md`](DECISIONS.md) (Q-056…Q-061, RQ-3, Q-050), задачи — раздел
«Этап 4» в [`backlog.md`](backlog.md).

| Блок | Что делаем |
|---|---|
| H1. Интеграционный API v1 | `/api/v1` 1:1 со старым (17 маршрутов, `resources/api/openapi-v1.yaml`): API-ключи, `api.scope`, `api.idempotent`, лимиты, тексты ошибок, журнал запросов; контрактные тесты против старой спецификации; вебхуки — тот же формат подписи и `event_id` (Q-056, Q-057). |
| H2. Telegram | Telegram Gateway (коды восстановления пароля для веба и гостя, коды подтверждения перевода баланса), бот оповещений платформы (Q-060), проверочное сообщение в суперадминке; лимиты как в старом; секреты зашифрованы. |
| H3. Мобильные приложения | Слой совместимости со старым REST для `mobileclient` (гостевые маршруты `routes/api.php`) и `mobileemployee` (`routes/api_staff.php`) поверх новых сервисов, токены как Sanctum; определение сервера клуба (Q-058), чтобы приложение работало и со старым, и с новым сервером во время поклубного перехода. |
| H4. Безопасность и эксплуатация | Шифрование секретов вебхуков и ключей интеграций (Q-050), шаг CI подписи обновлений агента Ed25519 и публикации манифеста, переводы kk/en для новых строк интерфейса. |

## Готово, когда

- Внешний интегратор, мобильное приложение клиента и приложение сотрудника работают с новым сервером без изменений.
- Восстановление пароля и подтверждение переводов приходят в Telegram; оповещения платформы работают.
- Секреты интеграций зашифрованы; обновление агента нельзя разослать без подписи из CI.
- CI зелёный.

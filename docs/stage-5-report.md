# Этап 5 — итоговый отчёт: перенос данных и новый агент

План — [`stage-5-plan.md`](stage-5-plan.md). Решения — `docs/open-questions/stage5-*.md`.

## Перенос данных (`migrate-from-mysql`, описание — `tools/migrate-from-mysql/README.md`)

| Команда | Что делает |
|---|---|
| `platform plan\|apply\|verify` | Один раз перед первым клубом: языки, переводы, тарифы SaaS, настройки платформы (секреты перешифровываются), новости платформы, суперадмины. |
| `plan --club` | Сухой прогон: строки по таблицам, конвертации, проблемы данных (значения вне CHECK, регистронезависимые дубли, отрицательные балансы, старые роли, настройки), сверка балансов с историей. |
| `apply --club` | Перенос одной транзакцией: id сохраняются (последовательности с запасом), деньги ×100 через строку, балансы — входящими остатками через ledger, JSON → v2, производные данные из журнала, токены приложений, API-ключи, вебхуки, секреты `APP_KEY` → новый ключ, файлы; сверка до коммита. Клуб остаётся закрытым (`imported`). |
| `verify --club` | Число строк, баланс каждого клиента = ledger, траты, склад, касса, ПК; расхождение — код выхода ≠ 0. |
| `go-live --club` | Открывает клуб; после этого удаление запрещено навсегда. |
| `purge --club --confirm <slug>` | Откат до открытия: удаляет перенесённый клуб для повторного переноса (только платформенная функция, ролям приложения недоступна). |

**Проверено:** настоящая схема MySQL (миграции старого проекта) с демо-данными → перенос → новый сервер на перенесённой базе: вход по старому паролю, X-отчёт = касса, мобильный токен и ключ интегратора принимаются, подпись вебхука совпадает со старым секретом.
**Объём:** 50 000 клиентов, 1 млн записей журнала, 300 000 кассовых операций — `apply` за 6 мин 50 с, пик памяти 163 МБ; другие клубы при этом работают.

## Новый агент (`agent/`, .NET 10)

- Служба Windows отдельно от интерфейса; интерфейс (WPF + WebView2) запускается только для экрана и общается со службой по локальному каналу, сети у него нет.
- Регистрация по коду и ключу образа, неэкспортируемый ключ (CNG/TPM), mTLS, поток команд с журналом и дедупликацией, все методы гостя, проверка подписи обновлений, Native AOT (служба ≈ 31 МБ).
- «На весь баланс» и автобиллинг считает сервер (Q-008); картинки клуба — через службу; ошибки — на языке гостя.
- Установщик Inno Setup собирается в CI; подпись обновлений Ed25519.
- Тесты: 142 unit, 15 тестов страницы, сквозной сценарий против настоящего Go-сервера; CI на Windows и Linux.

## Найдено и исправлено

- **Сервер:** отзыв прежнего сертификата при продлении закрывал поток уже на новом — ПК стирал ключ и выпадал из регистрации. Теперь поток закрывается по серийному номеру.
- **Сервер:** поиск счетов ledger полным просмотром на каждой денежной операции (~20 мс при 50 тыс. клиентов) → по индексу (0,2 мс).
- **Сервер:** токены гостя не отзывались при отключении ПК.
- **Тестовый стенд:** кириллица в MySQL хранилась искажённой (сверка сравнивала только числа).

## Что нужно до перевода первого клуба

1. **Проверка агента на Windows 10 и 11** по чек-листу `docs/agent-protocol.md` §14.9 — в среде разработки Windows не было.
2. **Ключ подписи обновлений агента** (Ed25519) и **сертификат Authenticode** — в секреты CI.
3. **Пояс сервера MySQL на проде** — сверить на копии базы (S5-M1-О1).
4. **Пилот на копии прода:** `platform apply` → `plan` клуба (разобрать блокеры) → `apply` → `verify` → проверка сотрудниками → `go-live`; маршрут nginx для клуба.

# Этап 2 — транспортный слой: авторизация, агент, события

Цель: подключить готовые денежные сервисы Этапа 1 к внешнему миру — админка (REST + WebSocket) и агент ПК (gRPC + mTLS).
Экраны React — Этап 3. Решения владельца по вопросам Этапа 1 пока не получены: работаем по
[`stage-1-assumptions.md`](stage-1-assumptions.md) и повторяем старое поведение.

## Волна A — основа (параллельно)

| Блок | Что делаем | Источник в Laravel |
|---|---|---|
| A1. Авторизация и права | Пароли Argon2id с прозрачной перехеш-миграцией старых bcrypt; вход сотрудника; короткий access-токен + ротация refresh-токена (хранение в Valkey, отзыв семейства при повторе); выбор клуба; роли и права (`ClubPermissions`, `ClubRoles`, `StaffPermissions`) как middleware; суперадмин и режим просмотра клуба; rate limiting в Valkey на тех же маршрутах, что `throttle:` | `app/Support/*Permissions*`, `ClubRoles`, `AppServiceProvider` (лимиты), контроллеры входа |
| A2. Агент: регистрация и mTLS | Свой CA, одноразовые коды регистрации ПК, `EnrollmentService` (CSR → сертификат), отзыв и продление, gRPC-сервер с mTLS, привязка сертификата к ПК и клубу | `ClubComputerRegistrar`, `ClubInstallationKey`, `routes/api.php` (enroll/register) |
| A3. Агент: поток и присутствие | `AgentService.Connect`: Hello, статус в памяти/Valkey (в Postgres — только изменения состояния), команды с `seq`/`command_id` и повторной доставкой после реконнекта, ack | `HeartbeatService.cs`, heartbeat-маршруты, `ComputerPower` |
| A4. События | Журнал действий (`activity_logs`) и вебхуки через outbox в той же транзакции + публикация в NATS JetStream; WebSocket-хаб админки по клубу (вместо 5 мест polling); общая библиотека «один исполнитель» для воркеров | `ActivityLogger`, `WebhookDispatcher`, `DeliverWebhook`, polling-экраны |

## Волна B — API поверх сервисов

- REST по OpenAPI (`api/openapi.yaml`, oapi-codegen strict server): касса, смены, X/Z, пополнения, возвраты, склад, клиенты и балансы, тарифы (чтение), карта клуба (состояние ПК).
- gRPC для агента: вход гостя, тарифы и покупка, завершение сессии, пакеты, магазин, друзья и переводы — поверх `billing/service`.
- Сквозные тесты: HTTP/gRPC → сервис → БД по P1-сценариям; лимиты; права; RLS.

## Готово, когда

- Сотрудник входит, видит только свой клуб и только разрешённые действия; суммы и ошибки те же, что в старом.
- ПК регистрируется по одноразовому коду, держит один поток, получает команды; heartbeat не пишет в Postgres.
- Админка получает обновления по WebSocket вместо опроса.
- CI зелёный, включая сквозные тесты.

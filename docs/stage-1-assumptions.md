# Этап 1 — рабочие допущения по открытым вопросам

Владелец дал старт Этапу 1 до ответов на топ-10 вопросов из [`OPEN_QUESTIONS.md`](OPEN_QUESTIONS.md).
Ниже — с чем мы работаем, пока нет решения. Каждое допущение можно отменить; код, который от него зависит,
помечен комментарием `// Допущение Этапа 1: Q-NNN`.

Общее правило: **повторяем старое поведение**. Отступаем от него только там, где старое поведение
невозможно в новой схеме или противоречит обязательным правилам `CLAUDE.md` (int64-тиыны, ledger).

| Вопрос | Допущение | Отступление от старого поведения |
|---|---|---|
| Q-001 Деньги в Postgres | `bigint` тиыны под прежними именами колонок (как в `0001_init.sql`); в Go — `money.Tiyn` | Нет: перенос `× 100` точный |
| Q-002 >2 знаков после точки | Повторяем старое поведение каждого места (касса округляет как MySQL `decimal(12,2)`, переводы отклоняют). Парсер в `money` поддерживает оба режима | Нет |
| Q-003 Суммы в JSON | Формат JSON в БД не меняем (тенге, как в старом). Перевод в тиыны — на границе чтения через `money` с PHP-совместимым округлением | Нет |
| Q-004 Отрицательные суммы | Новый код считает в `int64` и корректен для отрицательных значений. Старый баг `formatCents(-50) = "0.-50"` относится к строковому API агента, которого в новом протоколе нет. `CHECK (balance >= 0)` не добавляем, пока не проверены данные | Да (баг форматирования не переносится) |
| Q-006 GAP-сценарии | Прогоняем Pest-тестами в одноразовой копии Zafiro (`tools/php-oracle`); эталон — фактический результат старого кода | Нет |
| Q-007 Лимит продаж тарифа | Повторяем правило (кассовые продажи не расходуют лимит), но считаем по таблице покупок, а не по журналу действий | Да (источник счётчика) |
| Q-008 Автобиллинг и «весь баланс» | Формулу переносим в Go (сервер), числа те же, что в `WindowsAgent/Frontend/main.js` | Да (место расчёта) |
| Q-009 Бонус за пополнение | Буквально как в старом | Нет |
| Q-011 Сгорание пакетов | Сроки и суммы те же; сгорание пишется в ledger минут | Да (появляется запись) |
| Q-013 Способ оплаты в кассе | Колонка `payment_method` nullable, в отчётах не используется | Да (новое поле) |

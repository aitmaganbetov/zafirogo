# Этап 3 — экраны React

Цель: все экраны старого проекта (`docs/parts/10-screens.md`: 50 экранов + общие компоненты) на React —
**та же разметка и Tailwind-классы, те же данные и действия**, — поверх сервера Этапов 1–2. Для каждого экрана —
недостающие REST-эндпоинты, обновления по WebSocket вместо опроса и визуальное сравнение со старой страницей.
Решения — `DECISIONS.md`; задачи экранов из `backlog.md` («Этап 3 — экраны»).

## Волна 0 — основа (параллельно)

| Блок | Что делаем |
|---|---|
| F1. Каркас SPA | TanStack Router (файловые маршруты, те же URI, что в `routes/web.php`); вход/регистрация/выбор клуба/приглашения; API-клиент (access-токен в памяти, refresh-cookie, CSRF, повтор при 401); i18n с загрузкой переводов с сервера (ключ — русский текст, формат i18next); права из `/api/auth/me`; WebSocket-клиент и живые бейджи сайдбара; общие компоненты из `resources/views/components`; шрифты и иконки из npm (Q-064). Сервер: разбиение OpenAPI по разделам (каждый раздел — свой файл и свой сгенерированный пакет), эндпоинт переводов и их загрузка из `database/translations`. |
| F2. Визуальное сравнение | Один набор демо-данных (JSON) → загрузчик в старый Laravel (копия, PHP 8.4, sqlite) и в новый сервер (Postgres); Playwright снимает одни и те же страницы в обоих при одинаковом viewport, теме и времени; попиксельное сравнение с порогом и HTML-отчёт; запуск одной командой (`task visual`). |

## Волны 1–2 — экраны по разделам

Каждый агент: REST-эндпоинты своего раздела (свой файл OpenAPI), страницы React, обновления по WebSocket,
Vitest + Playwright (сценарии и визуальное сравнение).

1. Дашборд, карта клуба (самый сложный экран), список ПК, коды регистрации и ключи образа (Q-037).
2. Касса, склад, заказы с ПК, услуги.
3. Клиенты, сотрудники, приглашения, права.
4. Тарифы, бронирования, новости, задачи, чат, журнал действий.
5. Настройки клуба (8 страниц).
6. Суперадминка (10 экранов, свой домен — Q-069), редактор переводов.
7. QR-вход на ПК, публичные страницы, PWA и офлайн-страница, документация API.
